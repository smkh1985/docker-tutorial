Lesson 5 — Logs درس ۵ — لاگ‌ها

In Lesson 3, nginx printed its log to your terminal. With -d that log seemed to disappear. It didn't: Docker keeps everything a container prints. You'll read it with docker logs, and even watch your own browser visits appear.

در درس ۳، nginx لاگش را در ترمینال شما چاپ کرد. با -d به نظر رسید که لاگ ناپدید شد. ناپدید نشد: Docker هر چیزی را که کانتینر چاپ می‌کند نگه می‌دارد. آن را با docker logs می‌خوانید و حتی بازدیدهای مرورگر خودتان را در آن می‌بینید.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Start nginxاجرای nginx Doneانجام شد

Start nginx in the background, named web, reachable at localhost:8080, like in Lesson 4:

nginx را در پس‌زمینه، با نام web و در دسترس روی localhost:8080 اجرا کنید، مثل درس ۴:

bash
docker run -d --name web -p 8080:80 nginx

2 Read the logsخواندن لاگ‌ها Doneانجام شد

bash
docker logs web
output
/docker-entrypoint.sh: Configuration complete; ready for start up
2026/10/10 09:38:55 [notice] 1#1: nginx/1.31.6
2026/10/10 09:38:55 [notice] 1#1: start worker processes
...

These are the same lines you saw in Lesson 3 when the terminal was stuck. With -d, Docker saved them instead of showing them. docker logs prints everything saved so far, then gives you your prompt back.

این‌ها همان خط‌هایی هستند که در درس ۳، وقتی ترمینال گیر کرده بود، دیدید. با -d، Docker آن‌ها را به‌جای نمایش، ذخیره کرد. docker logs هر چیزی را که تا الان ذخیره شده چاپ می‌کند و بعد prompt را به شما برمی‌گرداند.

3 See your visit in the logبازدید خودتان را در لاگ ببینید Doneانجام شد

Open http://localhost:8080 in your browser, then read the logs again:

http://localhost:8080 را در مرورگر باز کنید و بعد دوباره لاگ‌ها را بخوانید:

bash
docker logs web

At the bottom there are new lines:

در پایین خروجی، خط‌های جدیدی آمده:

output
172.17.0.1 - - [10/Oct/2026:09:38:58 +0000] "GET / HTTP/1.1" 200 896 "-" "Mozilla/5.0 (X11; Linux x86_64) …"
2026/10/10 09:38:58 [error] 29#29: *1 open() "/usr/share/nginx/html/favicon.ico" failed (2: No such file or directory), …
172.17.0.1 - - [10/Oct/2026:09:38:58 +0000] "GET /favicon.ico HTTP/1.1" 404 555 "http://localhost:8080/" "Mozilla/5.0 …"

The first line is your visit:

خط اول بازدید شما است:

172.17.0.1Who asked: that's you, seen from inside the container's networkچه کسی درخواست داد: خود شما، از دید شبکه‌ی داخل کانتینر
[10/Oct/2026:09:38:58 +0000]When (in UTC time)چه زمانی (به وقت UTC)
"GET / HTTP/1.1"What was asked: the home page /چه چیزی خواسته شد: صفحه‌ی اصلی /
200The answer: 200 = OK, the page was sentپاسخ: 200 یعنی OK، صفحه ارسال شد
"Mozilla/5.0 …"Which browser askedکدام مرورگر درخواست داد
❓ What is the favicon.ico error with 404?❓ خطای favicon.ico با 404 چیست؟

Your browser also asks every website for a small icon to show on the tab, called favicon.ico. nginx's default site doesn't have one, so it answers 404 = Not Found and writes an [error] line. It's harmless. It's a good first example of an error in a log.

مرورگر شما از هر وب‌سایت یک آیکون کوچک هم برای نمایش روی تب می‌خواهد، به نام favicon.ico. سایت پیش‌فرض nginx این آیکون را ندارد، پس با 404 یعنی Not Found جواب می‌دهد و یک خط [error] می‌نویسد. بی‌خطر است. نمونه‌ی خوبی از یک خطا در لاگ است.

💡 Log too long? Show only the last lines with --tail, e.g. docker logs --tail 3 web.

💡 لاگ خیلی طولانی است؟ با --tail فقط خط‌های آخر را نشان دهید، مثلاً docker logs --tail 3 web.

4 Follow the log liveدنبال کردن زنده‌ی لاگ Doneانجام شد

Running docker logs again and again is tiring. Add -f (follow) to keep watching:

اجرای دوباره و دوباره‌ی docker logs خسته‌کننده است. -f (follow، یعنی دنبال کن) را اضافه کنید تا مدام تماشا کنید:

bash
docker logs -f web

The terminal is stuck again, like in Lesson 3. Now reload the browser tab a few times and watch: a new line appears for each visit, live.

ترمینال دوباره گیر کرده، مثل درس ۳. حالا چند بار تب مرورگر را reload کنید و تماشا کنید: برای هر بازدید، یک خط جدید زنده ظاهر می‌شود.

output
...
172.17.0.1 - - [10/Oct/2026:09:39:06 +0000] "GET / HTTP/1.1" 200 896 "-" "Mozilla/5.0 …"   # ← new, after a reload
█   ← waiting for more

When you're done watching, press Ctrl+C to get your terminal back.

وقتی تماشا تمام شد، Ctrl+C را بزنید تا ترمینال به شما برگردد.

5 Is the container still running?کانتینر هنوز روشن است؟ Doneانجام شد

In Lesson 3, Ctrl+C stopped nginx. What about now? List the running containers:

در درس ۳، Ctrl+C nginx را متوقف کرد. الان چطور؟ کانتینرهای در حال اجرا را فهرست کنید:

bash
docker ps
output
CONTAINER ID   IMAGE     COMMAND                  CREATED          STATUS          PORTS                                     NAMES
bdc691275a8c   nginx     "/docker-entrypoint.…"   14 seconds ago   Up 13 seconds   0.0.0.0:8080->80/tcp, [::]:8080->80/tcp   web

Still Up, and the page still loads in the browser.

هنوز Up است، و صفحه هنوز در مرورگر باز می‌شود.

🔑 In Lesson 3 your terminal was attached to the container, so Ctrl+C stopped it. With docker logs -f your terminal is only watching the log, so Ctrl+C stops the watching, not the container.

🔑 در درس ۳ ترمینال شما به کانتینر چسبیده بود، پس Ctrl+C آن را متوقف کرد. با docker logs -f ترمینال فقط لاگ را تماشا می‌کند، پس Ctrl+C فقط تماشا را متوقف می‌کند، نه کانتینر را.

6 Clean upتمیزکاری Doneانجام شد

Stop and delete web in one command, then check it's gone from all containers:

web را با یک دستور متوقف و حذف کنید، بعد بررسی کنید که از همه‌ی کانتینرها حذف شده:

bash
docker rm -f web
docker ps -a

The logs are stored with the container. Once you delete it, its logs are gone too.

لاگ‌ها همراه کانتینر ذخیره می‌شوند. وقتی کانتینر را حذف کنید، لاگ‌هایش هم حذف می‌شوند.
