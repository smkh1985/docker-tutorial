Time to put it all together. You'll build a small shop API in Python (FastAPI), package it with a Dockerfile, and run it with Compose next to a PostgreSQL database. Your data will survive in a volume.

2 The API codeکد API Doneانجام شد

List the Python libraries the API needs in requirements.txt:

کتابخانه‌های Python که API لازم دارد را در requirements.txt بنویسید:

requirements.txt
fastapi
uvicorn
psycopg[binary]

fastapi builds the API, uvicorn is the web server that runs it, and psycopg talks to PostgreSQL. Now the program, main.py:

fastapi API را می‌سازد، uvicorn وب‌سروری است که آن را اجرا می‌کند و psycopg با PostgreSQL صحبت می‌کند. حالا خود برنامه، main.py:

main.py
import os

import psycopg
from fastapi import FastAPI

app = FastAPI()
DATABASE_URL = os.environ["DATABASE_URL"]

with psycopg.connect(DATABASE_URL) as conn:
    conn.execute("CREATE TABLE IF NOT EXISTS products (name text)")


@app.get("/products")
def list_products():
    with psycopg.connect(DATABASE_URL) as conn:
        rows = conn.execute("SELECT name FROM products").fetchall()
    return [row[0] for row in rows]


@app.post("/products")
def add_product(name: str):
    with psycopg.connect(DATABASE_URL) as conn:
        conn.execute("INSERT INTO products (name) VALUES (%s)", (name,))
    return {"added": name}

You don't need to know Python well. What matters:

لازم نیست Python را خوب بلد باشید. چیزهای مهم:

  • It reads the database address from the environment variable DATABASE_URL (Lesson 11).آدرس دیتابیس را از متغیر محیطی DATABASE_URL می‌خواند (درس ۱۱).
  • At start, it creates the table products if it doesn't exist.در شروع، اگر جدول products نباشد آن را می‌سازد.
  • GET /products lists products; POST /products?name=… adds one.GET /products محصولات را فهرست می‌کند؛ POST /products?name=… یکی اضافه می‌کند.

3 The DockerfileDockerfile Doneانجام شد

Dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

The patterns from Lessons 19 and 20, with three things to notice:

الگوهای درس‌های ۱۹ و ۲۰، با سه نکته‌ی قابل توجه:

  • requirements.txt is copied and installed before the rest of the project (COPY . .), so changing your code won't reinstall the libraries (caching, Lesson 19).requirements.txt قبل از بقیه‌ی پروژه (COPY . .) کپی و نصب می‌شود، تا تغییر کد باعث نصب دوباره‌ی کتابخانه‌ها نشود (cache، درس ۱۹).
  • --host 0.0.0.0 makes uvicorn listen on all network addresses of the container. By default it would only accept connections from inside the container, and -p couldn't reach it.--host 0.0.0.0 باعث می‌شود uvicorn روی همه‌ی آدرس‌های شبکه‌ی کانتینر گوش دهد. به‌طور پیش‌فرض فقط اتصال‌های داخل کانتینر را قبول می‌کند و -p نمی‌تواند به آن برسد.
  • COPY . . would also copy db.env, the password file (Lesson 20). Create .dockerignore to keep it, and the build files, out of the image:COPY . . فایل db.env، یعنی فایل رمز را هم کپی می‌کند (درس ۲۰). .dockerignore را بسازید تا آن و فایل‌های ساخت را بیرون از ایمیج نگه دارد:

4 compose.yamlcompose.yaml Doneانجام شد

compose.yaml
services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      DATABASE_URL: postgresql://ali:secret@db:5432/shop
    restart: unless-stopped
  db:
    image: postgres:alpine
    env_file: db.env
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
build: .New: instead of image:, build the image from the Dockerfile in this folder (like docker build ., Lesson 17)جدید: به‌جای image:، ایمیج را از Dockerfile همین پوشه بساز (مثل docker build .، درس ۱۷)
environment:New: set environment variables, like -e (Lesson 11)جدید: تنظیم متغیرهای محیطی، مثل -e (درس ۱۱)
postgresql://ali:secret@db:5432/shopThe database address: user ali, password secret, host db (the service name, Lesson 15), port 5432, database shopآدرس دیتابیس: کاربر ali، رمز secret، host db (نام سرویس، درس ۱۵)، پورت 5432، دیتابیس shop
restart: unless-stoppedRestart policy (Lesson 12). You'll see why it matters in step 6سیاست راه‌اندازی مجدد (درس ۱۲). در قدم ۶ می‌بینید چرا مهم است

6 Why did the API restart?چرا API دوباره راه افتاد؟ Doneانجام شد

Read the api service's logs. Like docker logs (Lesson 5), but by service name:

لاگ‌های سرویس api را بخوانید. مثل docker logs (درس ۵)، ولی با نام سرویس:

bash
docker compose logs api
output
...
api-1  | psycopg.OperationalError: connection failed: connection to server at "172.26.0.2", port 5432 failed: Connection refused
...
api-1  | INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)

Both containers started at almost the same time. The API tried to connect while PostgreSQL was still starting, got Connection refused, and crashed. Then restart: unless-stopped (Lesson 12) started it again, and this time the database was ready: Uvicorn running. ✅

هر دو کانتینر تقریباً هم‌زمان شروع شدند. API وقتی PostgreSQL هنوز در حال شروع بود سعی کرد وصل شود، Connection refused گرفت و crash کرد. بعد restart: unless-stopped (درس ۱۲) دوباره راهش انداخت و این بار دیتابیس آماده بود: Uvicorn running. ✅

🔑 This happens a lot in real projects: an app starts faster than its database. A restart policy is the simplest fix.

🔑 این در پروژه‌های واقعی زیاد پیش می‌آید: برنامه سریع‌تر از دیتابیسش شروع می‌شود. سیاست راه‌اندازی مجدد ساده‌ترین راه‌حل است.

8 down, then up: is the data still there?down و دوباره up: داده‌ها هنوز هستند؟ Doneانجام شد

Remove the containers and network, then start the project again (Lesson 14):

کانتینرها و شبکه را حذف کنید و پروژه را دوباره اجرا کنید (درس ۱۴):

bash
docker compose down
docker compose up -d

Ask for the products again:

دوباره محصولات را بخواهید:

bash
curl localhost:8000/products
output
["coffee","tea"]

✅ New containers, same data: it lives in the pgdata volume (Lessons 9 and 15).

✅ کانتینرهای جدید، همان داده‌ها: در volume ای به نام pgdata است (درس‌های ۹ و ۱۵).

💡 Changed main.py? Run docker compose up -d --build: --build rebuilds your image first, then replaces the api container.

💡 main.py را تغییر دادید؟ docker compose up -d --build را بزنید: --build اول ایمیج شما را دوباره می‌سازد و بعد کانتینر api را جایگزین می‌کند.
