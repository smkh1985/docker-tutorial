Lesson 0 — Install Docker درس ۰ — نصب Docker

Before any Docker lesson, set up your machine once. You'll check your system, install the prerequisites, install Docker Engine from Docker's official repository, and test it.

قبل از شروع درس‌های Docker، سیستم خود را یک بار آماده کنید. سیستم را بررسی می‌کنید، پیش‌نیازها را نصب می‌کنید، Docker Engine را از مخزن رسمی Docker نصب می‌کنید و آن را تست می‌کنید.

The commands are for Ubuntu Linux (and Ubuntu-based distros like Linux Mint). Using Debian, macOS or Windows? See this section.

دستورها برای لینوکس Ubuntu (و توزیع‌های مبتنی بر Ubuntu مثل Linux Mint) هستند. اگر Debian، macOS یا Windows دارید، این بخش را ببینید.

🖱 Hover over (or tap) any part of a command, such as -y or -aG, to see what it does.

🖱 نشانگر ماوس را روی هر بخش از یک دستور ببرید (یا لمس کنید)، مثلاً -y یا -aG، تا توضیح آن را ببینید.

✔ Tick the checkboxes as you go. Your progress is saved in this browser.

✔ همین‌طور که جلو می‌روید تیک‌ها را بزنید. پیشرفت شما در همین مرورگر ذخیره می‌شود.

i What we'll installچه چیزهایی نصب می‌کنیم Doneانجام شد

“Docker” is really a few programs working together. One apt install gives you all of them:

«Docker» در واقع چند برنامه است که با هم کار می‌کنند. یک apt install همه‌ی آن‌ها را نصب می‌کند:

Packageبسته What it isچیست
docker-ceThe Docker daemon (dockerd): a background service that builds images and runs containersسرویس Docker (dockerd): برنامه‌ای که در پس‌زمینه اجرا می‌شود و ایمیج می‌سازد و کانتینر اجرا می‌کند
docker-ce-cliThe docker command you type. It only sends requests to the daemonدستور docker که شما تایپ می‌کنید. فقط درخواست‌ها را به سرویس می‌فرستد
containerd.ioThe low-level runtime that actually starts and stops containersruntime سطح پایین که در واقع کانتینرها را روشن و خاموش می‌کند
docker-buildx-pluginThe modern image builder behind docker buildسازنده‌ی مدرن ایمیج که پشت docker build کار می‌کند
docker-compose-plugindocker compose: run several containers together from one YAML filedocker compose: اجرای چند کانتینر با هم از روی یک فایل YAML

You need sudo rights, an internet connection, a 64-bit CPU, and at least 2 GB of RAM and 10 GB of free disk.

به دسترسی sudo، اینترنت، پردازنده‌ی ۶۴ بیتی، و حداقل ۲ گیگابایت RAM و ۱۰ گیگابایت فضای خالی دیسک نیاز دارید.

1 Check your systemبررسی سیستم Doneانجام شد

Run these one by one and compare with the expected values:

این دستورها را یکی‌یکی اجرا کنید و با مقدارهای مورد انتظار مقایسه کنید:

bash
uname -m              # CPU type: x86_64 or aarch64
cat /etc/os-release   # distro name and version
nproc                 # number of CPU cores
free -h               # memory: look at "available"
df -h /               # free disk space: look at "Avail"

2 Remove old versions and install prerequisitesحذف نسخه‌های قدیمی و نصب پیش‌نیازها Doneانجام شد

2.1 · Remove conflicting packages۲.۱ · حذف بسته‌های ناسازگار

Ubuntu ships its own unofficial Docker packages. They conflict with the official ones, so remove them if present. It's safe to run even if none are installed.

Ubuntu بسته‌های غیررسمی Docker خودش را دارد. این‌ها با بسته‌های رسمی تداخل دارند، پس اگر نصب هستند حذفشان کنید. اگر هیچ‌کدام نصب نباشد هم اجرای این دستور بی‌خطر است.

bash
sudo apt remove $(dpkg --get-selections docker.io docker-compose docker-compose-v2 docker-doc podman-docker containerd runc | cut -f1)
sudo snap remove docker   # only if you installed Docker as a snap
❓ What does the $(dpkg … | cut -f1) part do?❓ بخش $(dpkg … | cut -f1) چه کار می‌کند؟

It runs first and prints only the names from that list that are actually installed. Those names are passed to apt remove, so apt never complains about a package you don't have.

این بخش اول اجرا می‌شود و فقط نام بسته‌هایی از آن فهرست را که واقعاً نصب هستند چاپ می‌کند. همین نام‌ها به apt remove داده می‌شوند، پس apt درباره‌ی بسته‌ای که ندارید خطا نمی‌دهد.

2.2 · Install the prerequisites۲.۲ · نصب پیش‌نیازها

ca-certificates lets your system trust HTTPS websites, and curl downloads files. We need both to fetch Docker's signing key.

ca-certificates باعث می‌شود سیستم به سایت‌های HTTPS اعتماد کند و curl فایل دانلود می‌کند. برای گرفتن کلید امضای Docker به هر دو نیاز داریم.

bash
sudo apt update
sudo apt install -y ca-certificates curl
Checklistچک‌لیست

3 Add Docker's official apt repositoryاضافه کردن مخزن رسمی apt داکر Doneانجام شد

We tell apt where to download Docker from, and give it Docker's key so it can check the packages are genuine.

به apt می‌گوییم Docker را از کجا دانلود کند و کلید Docker را به آن می‌دهیم تا بتواند اصل بودن بسته‌ها را بررسی کند.

3.1 · Download Docker's signing key۳.۱ · دانلود کلید امضای Docker

bash
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

3.2 · Add the repository۳.۲ · اضافه کردن مخزن

Copy and paste the whole block at once. It writes a small config file for apt:

کل این بلوک را یک‌جا کپی و paste کنید. یک فایل تنظیمات کوچک برای apt می‌نویسد:

bash
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
❓ What does the Suites: $( … ) line do?❓ خط Suites: $( … ) چه کار می‌کند؟

It reads /etc/os-release and inserts your Ubuntu codename, e.g. noble for 24.04. On Linux Mint it picks the Ubuntu codename Mint is based on, which is what Docker's repository expects.

فایل /etc/os-release را می‌خواند و اسم رمز نسخه‌ی Ubuntu شما را قرار می‌دهد، مثلاً noble برای 24.04. روی Linux Mint اسم رمز Ubuntuای را برمی‌دارد که Mint بر پایه‌ی آن ساخته شده؛ همان چیزی که مخزن Docker انتظار دارد.

Check the file looks right, with a real codename and not an empty Suites: line:

بررسی کنید فایل درست است و خط Suites: خالی نیست و یک اسم رمز واقعی دارد:

bash
cat /etc/apt/sources.list.d/docker.sources

✅ In the output of sudo apt update you should see a line containing download.docker.com with no errors.

✅ در خروجی sudo apt update باید خطی شامل download.docker.com ببینید، بدون خطا.

4 Install Docker Engineنصب Docker Engine Doneانجام شد

bash
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

The Docker service starts automatically. Check that it's running and will start on every boot:

سرویس Docker به‌طور خودکار روشن می‌شود. بررسی کنید که در حال اجراست و با هر بار روشن شدن سیستم هم اجرا می‌شود:

bash
systemctl is-active docker    # expect: active
systemctl is-enabled docker   # expect: enabled

If either one says something else, start and enable it:

اگر هر کدام چیز دیگری نشان داد، سرویس را روشن و فعال کنید:

bash
sudo systemctl enable --now docker.service containerd.service

Want to know which version you got? sudo docker version shows two parts: Client (the CLI) and Server (the daemon). If Server is missing, the daemon isn't running.

می‌خواهید بدانید چه نسخه‌ای نصب شد؟ sudo docker version دو بخش نشان می‌دهد: Client (دستور CLI) و Server (سرویس). اگر بخش Server نباشد، سرویس اجرا نمی‌شود.

5 Run Docker without sudoاجرای Docker بدون sudo Doneانجام شد

The docker CLI talks to the daemon through a file called /var/run/docker.sock. Only root and members of the docker group may use it, so add yourself to that group:

دستور docker از طریق فایلی به نام /var/run/docker.sock با سرویس صحبت می‌کند. فقط root و اعضای گروه docker اجازه‌ی استفاده از آن را دارند، پس خودتان را به این گروه اضافه کنید:

bash
sudo usermod -aG docker $USER
newgrp docker          # or log out and log back in
groups                 # "docker" should be in the list

newgrp only affects the current terminal. If another terminal says permission denied, log out and log back in (or reboot).

newgrp فقط روی همین ترمینال اثر دارد. اگر ترمینال دیگری خطای permission denied داد، یک بار log out و دوباره log in کنید (یا سیستم را ری‌استارت کنید).

Test itتست کنید

bash
docker run --rm hello-world

✅ You should see “Hello from Docker!”. Docker is installed. What actually happened here is the topic of the next lessons.

✅ باید پیام «Hello from Docker!» را ببینید. Docker نصب شد. اینکه دقیقاً چه اتفاقی افتاد موضوع درس‌های بعدی است.

⚠ Being in the docker group is as powerful as root: anyone in it can start a container that reads any file on the machine. That's fine on your own laptop. On a shared server, only add trusted users.

⚠ عضویت در گروه docker به اندازه‌ی root قدرت دارد: هر عضو آن می‌تواند کانتینری اجرا کند که هر فایلی روی سیستم را بخواند. روی لپ‌تاپ شخصی مشکلی نیست. روی سرور مشترک فقط کاربران مورد اعتماد را اضافه کنید.

🖥Debian, macOS or WindowsDebian، macOS یا Windows

Debian

Follow the same steps, but in Step 3 replace linux/ubuntu with linux/debian in both URLs (the key and URIs:). The Suites: line works as is.

همین قدم‌ها را دنبال کنید، فقط در قدم ۳ در هر دو آدرس (کلید و URIs:) عبارت linux/ubuntu را با linux/debian عوض کنید. خط Suites: بدون تغییر کار می‌کند.

macOS

Install Docker Desktop (pick Apple Silicon or Intel), open it once, and wait for the whale icon to say running.

Docker Desktop را نصب کنید (نسخه‌ی Apple Silicon یا Intel)، یک بار بازش کنید و صبر کنید تا آیکون نهنگ وضعیت running را نشان دهد.

Windows

Docker Desktop needs WSL 2. In PowerShell as Administrator:

Docker Desktop به WSL 2 نیاز دارد. در PowerShell با دسترسی Administrator:

powershell
wsl --install            # then reboot
winget install Docker.DockerDesktop

After installing, run docker run --rm hello-world to test it.

بعد از نصب، با docker run --rm hello-world آن را تست کنید.

Start over completely. This uninstalls Docker and deletes all images, containers and volumes:

شروع کاملاً از اول. این دستورها Docker را حذف می‌کنند و همه‌ی ایمیج‌ها، کانتینرها و volumeها را پاک می‌کنند:

bash
sudo apt purge -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo rm -rf /var/lib/docker /var/lib/containerd

🎉 Docker is ready!Docker آماده است!
