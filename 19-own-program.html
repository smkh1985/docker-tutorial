Lesson 19 — Package your own program درس ۱۹ — بسته‌بندی برنامه‌ی خودتان

In Lesson 17 your image only served a file. Real images run a program, and that program needs things installed. You'll package a small Python program with three new Dockerfile instructions: WORKDIR, RUN and CMD. Then it runs on any PC with Docker, even with no Python installed.

در درس ۱۷ ایمیج شما فقط یک فایل را سرو می‌کرد. ایمیج‌های واقعی یک برنامه اجرا می‌کنند، و آن برنامه به چیزهای نصب‌شده نیاز دارد. یک برنامه‌ی کوچک Python را با سه دستور جدید Dockerfile بسته‌بندی می‌کنید: WORKDIR، RUN و CMD. بعد روی هر کامپیوتری که Docker دارد اجرا می‌شود، حتی بدون نصب Python.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Write a small programنوشتن یک برنامه‌ی کوچک Doneانجام شد

Make a project folder called hello-app in your home folder and go into it:

یک پوشه‌ی پروژه به نام hello-app در پوشه‌ی خانه‌تان بسازید و واردش شوید:

bash
mkdir ~/hello-app
cd ~/hello-app

Create app.py with nano:

با nano فایل app.py را بسازید:

app.py
import cowsay

cowsay.cow("Hello from my own image!")

It uses cowsay, a small Python library that draws a talking cow. It is not part of Python, so it must be installed first. That's the job of the Dockerfile.

از cowsay استفاده می‌کند، یک کتابخانه‌ی کوچک Python که یک گاو سخنگو می‌کشد. جزو Python نیست، پس اول باید نصب شود. این کار Dockerfile است.

2 Write the Dockerfileنوشتن Dockerfile Doneانجام شد

In the same folder, create Dockerfile with nano:

در همان پوشه، با nano فایل Dockerfile را بسازید:

Dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY app.py .
RUN pip install cowsay
CMD ["python", "app.py"]
FROM python:3.13-slimStart from the official Python image, a slim (smaller) version with Python 3.13 already installedاز ایمیج رسمی Python شروع کن، نسخه‌ی slim (کوچک‌تر) که Python 3.13 از قبل رویش نصب است
WORKDIR /appNew: create the folder /app in the image and work there from now on, like mkdir + cdجدید: پوشه‌ی /app را در ایمیج بساز و از این به بعد همان‌جا کار کن، مثل mkdir + cd
COPY app.py .Copy your program in (Lesson 17). . means “here”, the WORKDIR: /appبرنامه‌تان را کپی کن (درس ۱۷). . یعنی «همین‌جا»، یعنی WORKDIR: /app
RUN pip install cowsayNew: run a command while building. Here: install cowsay into the imageجدید: یک دستور را هنگام ساختن اجرا کن. اینجا: cowsay را داخل ایمیج نصب کن
CMD ["python", "app.py"]New: the command a container runs when it starts. You saw nginx's CMD in docker history (Lesson 16)جدید: دستوری که کانتینر هنگام شروع اجرا می‌کند. CMD مربوط به nginx را در docker history دیدید (درس ۱۶)

🔑 RUN happens once, when you build the image. CMD happens every time a container starts.

🔑 RUN یک بار، هنگام ساختن ایمیج اجرا می‌شود. CMD هر بار که یک کانتینر شروع می‌شود اجرا می‌شود.

3 Build and runساخت و اجرا Doneانجام شد

Build the image and call it hello-app (Lesson 17):

ایمیج را بسازید و نامش را hello-app بگذارید (درس ۱۷):

bash
docker build -t hello-app .
output
 => [1/4] FROM docker.io/library/python:3.13-slim@sha256:70729b46c69b4f1e
 => [2/4] WORKDIR /app
 => [3/4] COPY app.py .
 => [4/4] RUN pip install cowsay          # installing, at build time
 ...
 => => naming to docker.io/library/hello-app:latest

Now run it in a new container, and delete the container when it's done (Lesson 7):

حالا آن را در یک کانتینر جدید اجرا کنید و وقتی تمام شد کانتینر را حذف کنید (درس ۷):

bash
docker run --rm hello-app
output
  ________________________
| Hello from my own image! |
  ========================
                        \
                         \
                           ^__^
                           (oo)\_______
                           (__)\       )\/\
                               ||----w |
                               ||     ||

🐄 The container ran your CMD: python app.py. Python and cowsay were already inside the image.

🐄 کانتینر CMD شما را اجرا کرد: python app.py. Python و cowsay از قبل داخل ایمیج بودند.

4 Change the program and rebuildتغییر برنامه و ساخت دوباره Doneانجام شد

Open app.py with nano and change the text to "Version 2 of my app!". Then build again, the same way as in step 3:

app.py را با nano باز کنید و متن را به "Version 2 of my app!" تغییر دهید. بعد دوباره، مثل قدم ۳، بسازید:

bash
docker build -t hello-app .
output
[+] Building 12.4s (9/9) FINISHED
 => [1/4] FROM docker.io/library/python:3.13-slim@sha256:70729b46c69b4f1e
 => CACHED [2/4] WORKDIR /app
 => [3/4] COPY app.py .                   # your code changed
 => [4/4] RUN pip install cowsay          # ← installing AGAIN?!

You only changed one line of your code, so why did Docker install cowsay again?

شما فقط یک خط از کدتان را عوض کردید، پس چرا Docker دوباره cowsay را نصب کرد؟

Each line of the Dockerfile makes one layer. Docker reuses (CACHED) a layer if nothing it depends on changed. But once one layer changes, every layer after it is rebuilt. app.py changed, so the COPY layer changed, so the RUN layer after it was redone, even though cowsay didn't change at all.

هر خط Dockerfile یک لایه می‌سازد. Docker لایه‌ای را که هیچ چیزِ وابسته‌اش تغییر نکرده دوباره استفاده می‌کند (CACHED). ولی وقتی یک لایه تغییر کند، همه‌ی لایه‌های بعد از آن دوباره ساخته می‌شوند. app.py عوض شد، پس لایه‌ی COPY عوض شد، پس لایه‌ی RUN بعد از آن دوباره انجام شد، با اینکه cowsay اصلاً تغییری نکرده بود.

5 Fix the orderدرست کردن ترتیب Doneانجام شد

Open Dockerfile and move COPY app.py . to the line after RUN pip install cowsay:

Dockerfile را باز کنید و COPY app.py . را به خط بعد از RUN pip install cowsay ببرید:

Dockerfile
FROM python:3.13-slim
WORKDIR /app
RUN pip install cowsay
COPY app.py .
CMD ["python", "app.py"]

Build once to apply the new order. pip install runs one last time, because its position changed:

یک بار بسازید تا ترتیب جدید اعمال شود. pip install یک بار دیگر اجرا می‌شود، چون جایش عوض شد:

bash
docker build -t hello-app .

Now change app.py again, to "Version 3 of my app!", and build again:

حالا دوباره app.py را تغییر دهید، به "Version 3 of my app!"، و دوباره بسازید:

bash
docker build -t hello-app .
output
[+] Building 5.6s (9/9) FINISHED
 => [1/4] FROM docker.io/library/python:3.13-slim@sha256:70729b46c69b4f1e
 => CACHED [2/4] WORKDIR /app
 => CACHED [3/4] RUN pip install cowsay   # ← reused!
 => [4/4] COPY app.py .                   # only your code

✅ pip install is CACHED now: only your code was copied. The build took 5.6 s instead of 12.4 s. With big projects, that's minutes saved on every build. Run it (same as step 3):

✅ حالا pip install در وضعیت CACHED است: فقط کد شما کپی شد. ساخت به‌جای ۱۲٫۴ ثانیه ۵٫۶ ثانیه طول کشید. در پروژه‌های بزرگ، این یعنی صرفه‌جویی چند دقیقه در هر ساخت. اجرایش کنید (مثل قدم ۳):

bash
docker run --rm hello-app
output
  ____________________
| Version 3 of my app! |
  ====================
  ...

🔑 Order matters. Put what changes rarely first (installing libraries), and what changes often last (your code).

🔑 ترتیب مهم است. چیزی را که به‌ندرت عوض می‌شود اول بگذارید (نصب کتابخانه‌ها) و چیزی را که زیاد عوض می‌شود آخر (کد شما).

6 Clean upتمیزکاری Doneانجام شد

Thanks to --rm there are no containers to delete. Delete the image if you like (Lesson 1):

به لطف --rm کانتینری برای حذف وجود ندارد. اگر خواستید ایمیج را حذف کنید (درس ۱):

bash
docker image rm hello-app
