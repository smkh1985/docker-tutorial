Lesson 8 — Keep your data with volumes درس ۸ — نگه داشتن داده‌ها با volume

Containers are ephemeral (temporary): when you delete a container, everything inside it is deleted too. You saw this in Lesson 6.

کانتینرها موقتی هستند (ephemeral): وقتی کانتینری را حذف می‌کنید، همه‌ی محتوای داخلش هم حذف می‌شود. این را در درس ۶ دیدید.

But some files must survive: a database, your program's outputs, uploaded files, build artifacts… You'll first lose a pretend database, then save it with a volume.

ولی بعضی فایل‌ها باید باقی بمانند: یک دیتابیس، خروجی‌های برنامه، فایل‌های آپلودشده، آرتیفکت‌ها (فایل‌هایی که هنگام ساختن برنامه تولید می‌شوند) و … اول یک دیتابیس فرضی را از دست می‌دهید، بعد با یک volume نجاتش می‌دهید.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Save a “database” inside a containerذخیره‌ی یک «دیتابیس» داخل کانتینر Doneانجام شد

Start nginx in the background and name it app. We don't need a port this time:

nginx را در پس‌زمینه اجرا کنید و نامش را app بگذارید. این بار پورت لازم نداریم:

bash
docker run -d --name app nginx

Open a shell inside app:

یک شل داخل app باز کنید:

bash
docker exec -it app bash

Pretend the file /data/db.txt is your app's database. Create the folder, save a record in it, and read it back:

فرض کنید فایل /data/db.txt دیتابیس برنامه‌ی شماست. پوشه را بسازید، یک رکورد در آن ذخیره کنید و دوباره بخوانیدش:

bash · inside
mkdir /data
echo "Ali, balance: 100" > /data/db.txt
cat /data/db.txt
output
Ali, balance: 100

Leave the shell:

از شل خارج شوید:

bash · inside
exit

2 Delete the container: is the database still there?حذف کانتینر: دیتابیس هنوز هست؟ Doneانجام شد

Stop and delete app in one command, then start a new one exactly like in step 1:

app را با یک دستور متوقف و حذف کنید، بعد یک کانتینر جدید دقیقاً مثل قدم ۱ اجرا کنید:

bash
docker rm -f app
docker run -d --name app nginx

Look for the database. This time, run just one command with exec. Without -it, Docker runs it, prints the result, and you stay on your PC:

دنبال دیتابیس بگردید. این بار فقط یک دستور را با exec اجرا کنید. بدون -it، Docker آن را اجرا می‌کند، نتیجه را چاپ می‌کند و شما روی کامپیوتر خودتان می‌مانید:

bash
docker exec app cat /data/db.txt
output
cat: /data/db.txt: No such file or directory

❌ The database is gone. It lived inside the old container, and was deleted with it. Imagine this was your real users' data!

❌ دیتابیس از بین رفت. داخل کانتینر قبلی بود و همراه آن حذف شد. تصور کنید این داده‌های واقعی کاربرانتان بود!

Delete this container too, so we can do it the right way:

این کانتینر را هم حذف کنید تا کار را درست انجام دهیم:

bash
docker rm -f app

3 Add a volume with -vاضافه کردن volume با -v Doneانجام شد

The fix: keep /data outside the container, in a folder on your PC. First make that folder:

راه‌حل: /data را بیرون از کانتینر، در یک پوشه روی کامپیوترتان نگه دارید. اول آن پوشه را بسازید:

bash
mkdir ~/my-data

Start app again, plus -v:

app را دوباره اجرا کنید، به‌اضافه‌ی -v:

bash
docker run -d --name app -v ~/my-data:/data nginx

-v means volume. It works like -p, but for folders: your PC first, then the container.

-v یعنی volume. مثل -p کار می‌کند ولی برای پوشه‌ها: اول کامپیوتر شما، بعد کانتینر.

~/my-dataThe folder on your PCپوشه روی کامپیوتر شما
/dataWhere it appears inside the containerجایی که داخل کانتینر دیده می‌شود
Your PCکامپیوتر شما~/my-data
-v same folder, seen from both sidesیک پوشه، از هر دو طرف
Containerکانتینر app/data

It's not a copy: the container reads and writes your PC's folder directly. (Sharing a folder from your PC like this is called a bind mount.)

این یک کپی نیست: کانتینر مستقیماً در پوشه‌ی کامپیوتر شما می‌خواند و می‌نویسد. (به اشتراک گذاشتن یک پوشه‌ی کامپیوتر به این شکل bind mount نام دارد.)

4 Save the database againذخیره‌ی دوباره‌ی دیتابیس Doneانجام شد

Go inside app, save the same record in /data/db.txt, and leave. (/data already exists now, so no mkdir.)

به داخل app بروید، همان رکورد را در /data/db.txt ذخیره کنید و خارج شوید. (/data حالا وجود دارد، پس mkdir لازم نیست.)

bash
docker exec -it app bash
bash · inside
echo "Ali, balance: 100" > /data/db.txt
exit

Now look on your PC, outside any container:

حالا روی کامپیوتر خودتان، بیرون از هر کانتینری، نگاه کنید:

bash
cat ~/my-data/db.txt
output
Ali, balance: 100

The container wrote the database into your PC's folder.

کانتینر دیتابیس را در پوشه‌ی کامپیوتر شما نوشت.

❓ I can read db.txt on my PC but can't edit it?❓ می‌توانم db.txt را روی کامپیوترم بخوانم ولی نمی‌توانم ویرایشش کنم؟

Inside the container you were root, so the file belongs to root on your PC too (ls -l ~/my-data shows it). Your normal user can read it, but changing it gives permission denied. Use sudo if you really need to edit it.

داخل کانتینر شما root بودید، پس فایل روی کامپیوترتان هم مال root است (ls -l ~/my-data این را نشان می‌دهد). کاربر معمولی شما می‌تواند آن را بخواند ولی تغییرش خطای permission denied می‌دهد. اگر واقعاً لازم است ویرایشش کنید، از sudo استفاده کنید.

5 Delete the container again: does the database survive?حذف دوباره‌ی کانتینر: دیتابیس باقی می‌ماند؟ Doneانجام شد

Delete app in one command, then start a new one exactly like in step 3 (with the same -v):

app را با یک دستور حذف کنید، بعد یک کانتینر جدید دقیقاً مثل قدم ۳ (با همان -v) اجرا کنید:

bash
docker rm -f app
docker run -d --name app -v ~/my-data:/data nginx

Read the database inside the new container, with one command like in step 2:

دیتابیس را داخل کانتینر جدید، با یک دستور مثل قدم ۲ بخوانید:

bash
docker exec app cat /data/db.txt
output
Ali, balance: 100

✅ The database survived! The new container found it, because it was never inside the container: it's on your PC.

✅ دیتابیس باقی ماند! کانتینر جدید آن را پیدا کرد، چون هیچ‌وقت داخل کانتینر نبود: روی کامپیوتر شماست.

Without -v (step 2)بدون -v (قدم ۲) With -v (step 5)با -v (قدم ۵)
db.txt livesdb.txt کجاستinside the containerداخل کانتینرon your PCروی کامپیوتر شما
After docker rmبعد از docker rm❌ goneاز بین رفت✅ keptباقی ماند

🔑 Containers are temporary; volumes are not. Put anything you want to keep (databases, outputs, artifacts) in a volume.

🔑 کانتینرها موقتی هستند؛ volumeها نه. هر چیزی را که می‌خواهید نگه دارید (دیتابیس‌ها، خروجی‌ها، آرتیفکت‌ها) در یک volume بگذارید.

6 Clean upتمیزکاری Doneانجام شد

bash
docker rm -f app

Deleting the container doesn't touch ~/my-data: db.txt is still on your PC.

حذف کانتینر به ~/my-data دست نمی‌زند: db.txt هنوز روی کامپیوتر شماست.

💡 Can Docker manage the storage folder for you, instead of a PC folder? Yes: that's a named volume, the next lesson.

💡 Docker می‌تواند به‌جای پوشه‌ی کامپیوتر، خودش محل ذخیره‌سازی را مدیریت کند؟ بله: اسمش named volume است، موضوع درس بعد.
