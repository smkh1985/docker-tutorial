Lesson 11 — Settings with environment variables درس ۱۱ — تنظیمات با متغیرهای محیطی

Many ready-made images need settings before they can start: a password, a user name, a database name… You give them these settings as environment variables, without changing the image.

خیلی از ایمیج‌های آماده قبل از شروع به تنظیمات نیاز دارند: یک رمز عبور، یک نام کاربری، یک نام دیتابیس… این تنظیمات را به‌صورت متغیرهای محیطی (environment variable) به آن‌ها می‌دهید، بدون تغییر ایمیج.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Run PostgreSQLاجرای PostgreSQL Doneانجام شد

PostgreSQL is one of the most used databases in the world. Start it in the background and name it db:

PostgreSQL یکی از پراستفاده‌ترین دیتابیس‌های دنیاست. آن را در پس‌زمینه اجرا کنید و نامش را db بگذارید:

bash
docker run -d --name db postgres:alpine

The first time it downloads the image (about 120 MB). Now check whether it's running. List all containers:

بار اول ایمیج را دانلود می‌کند (حدود ۱۲۰ مگابایت). حالا بررسی کنید که در حال اجراست یا نه. همه‌ی کانتینرها را فهرست کنید:

bash
docker ps -a
output
NAMES     STATUS                       # other columns left out
db        Exited (1) 3 seconds ago

❌ Exited (1): it stopped right away, and 1 means an error (0 was “OK” in Lesson 2).

❌ Exited (1): بلافاصله متوقف شد، و 1 یعنی خطا (در درس ۲، 0 یعنی «OK» بود).

2 Why did it stop? Read the logsچرا متوقف شد؟ لاگ‌ها را بخوانید Doneانجام شد

When a container stops with an error, the first thing to do is read what it printed (Lesson 5):

وقتی کانتینری با خطا متوقف می‌شود، اولین کار خواندن چیزی است که چاپ کرده (درس ۵):

bash
docker logs db
output
Error: Database is uninitialized and superuser password is not specified.
       You must specify POSTGRES_PASSWORD to a non-empty value for the
       superuser. For example, "-e POSTGRES_PASSWORD=password" on "docker run".
...

PostgreSQL refuses to start without a password, and it tells you exactly what to do: set POSTGRES_PASSWORD with -e.

PostgreSQL بدون رمز عبور اجرا نمی‌شود، و دقیقاً می‌گوید چه کار کنید: POSTGRES_PASSWORD را با -e تنظیم کنید.

Delete the failed container:

کانتینر شکست‌خورده را حذف کنید:

bash
docker rm db

3 Fix it with -eرفع با -e Doneانجام شد

bash
docker run -d --name db -e POSTGRES_PASSWORD=secret postgres:alpine

-e means environment variable, written NAME=value. The program inside the container reads it when it starts. Check it's running:

-e یعنی متغیر محیطی (environment variable)، به شکل NAME=value. برنامه‌ی داخل کانتینر هنگام شروع آن را می‌خواند. بررسی کنید که در حال اجراست:

bash
docker ps
output
NAMES     STATUS          # other columns left out
db        Up 4 seconds

✅ Up. The last line of docker logs db now says database system is ready to accept connections.

✅ Up. آخرین خط docker logs db حالا می‌گوید database system is ready to accept connections.

💡 Which variables does an image understand? Its page on Docker Hub lists them, e.g. POSTGRES_PASSWORD, POSTGRES_USER, POSTGRES_DB.

💡 یک ایمیج چه متغیرهایی را می‌فهمد؟ صفحه‌اش در Docker Hub آن‌ها را فهرست کرده، مثلاً POSTGRES_PASSWORD، POSTGRES_USER، POSTGRES_DB.

4 See the variables inside the containerدیدن متغیرها داخل کانتینر Doneانجام شد

Run one command inside db: env lists all environment variables:

یک دستور داخل db اجرا کنید: env همه‌ی متغیرهای محیطی را فهرست می‌کند:

bash
docker exec db env
output
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
HOSTNAME=35f390d3120d
POSTGRES_PASSWORD=secret              # ← yours, from -e
LANG=en_US.utf8
PG_VERSION=18.6                       # set by the image itself
PGDATA=/var/lib/postgresql/18/docker
...

Your variable is there. The others were set by the image's authors, e.g. PG_VERSION. PGDATA is where PostgreSQL keeps its data: that's where a volume would go (Lesson 9).

متغیر شما آنجاست. بقیه را سازندگان ایمیج تنظیم کرده‌اند، مثلاً PG_VERSION. PGDATA جایی است که PostgreSQL داده‌هایش را نگه می‌دارد: یک volume باید همان‌جا قرار بگیرد (درس ۹).

Delete db in one command:

db را با یک دستور حذف کنید:

bash
docker rm -f db

5 Many settings? Use an env fileتنظیمات زیاد؟ از env file استفاده کنید Doneانجام شد

Let's also choose our own user name and database name. With -e the command gets long:

بیایید نام کاربر و نام دیتابیس را هم خودمان انتخاب کنیم. با -e دستور طولانی می‌شود:

just look, don't run
docker run -d --name db -e POSTGRES_USER=ali -e POSTGRES_PASSWORD=secret -e POSTGRES_DB=shop postgres:alpine

Instead, put the settings in a file, one NAME=value per line. Make a folder and create the file db.env:

به‌جای آن، تنظیمات را در یک فایل بگذارید، در هر خط یک NAME=value. یک پوشه بسازید و فایل db.env را ایجاد کنید:

bash
mkdir ~/pg-demo
cd ~/pg-demo
nano db.env
db.env
POSTGRES_USER=ali
POSTGRES_PASSWORD=secret
POSTGRES_DB=shop

Save and exit (Ctrl+O, Enter, Ctrl+X). No spaces around =, and no quotes. Now run with --env-file:

ذخیره کنید و خارج شوید (Ctrl+O، Enter، Ctrl+X). دور = فاصله نگذارید و از کوتیشن استفاده نکنید. حالا با --env-file اجرا کنید:

bash
docker run -d --name db --env-file db.env postgres:alpine

Short, and the settings are easy to read and change. Did they work? Ask PostgreSQL who you are and which database you're in (wait a few seconds for it to start first):

کوتاه است و تنظیمات راحت خوانده و عوض می‌شوند. کار کرد؟ از PostgreSQL بپرسید شما کی هستید و در کدام دیتابیس هستید (اول چند ثانیه صبر کنید تا اجرا شود):

bash
docker exec db psql -U ali -d shop -c "SELECT current_user, current_database();"
output
 current_user | current_database
--------------+------------------
 ali          | shop
(1 row)

✅ User ali and database shop, both from db.env. (psql is PostgreSQL's command-line tool, like redis-cli in Lesson 9.)

✅ کاربر ali و دیتابیس shop، هر دو از db.env. (psql ابزار خط فرمان PostgreSQL است، مثل redis-cli در درس ۹.)

6 Keep secrets safe, and clean upامن نگه داشتن رمزها، و تمیزکاری Doneانجام شد

Environment variables are not hidden. Anyone who can use Docker on this PC can read them:

متغیرهای محیطی پنهان نیستند. هر کسی که روی این کامپیوتر به Docker دسترسی دارد می‌تواند آن‌ها را بخواند:

bash
docker inspect db
output
            "Env": [
                "POSTGRES_USER=ali",
                "POSTGRES_PASSWORD=secret",       # in plain text!
                "POSTGRES_DB=shop",
                ...

⚠ An env file holds passwords. Never put it in git or share it: add its name to .gitignore. Use real, strong passwords outside of practice.

⚠ env file رمزهای عبور را در خود دارد. هرگز آن را در git نگذارید یا به اشتراک نگذارید: نامش را به .gitignore اضافه کنید. بیرون از تمرین از رمزهای واقعی و قوی استفاده کنید.

Clean up: delete db in one command:

تمیزکاری: db را با یک دستور حذف کنید:

bash
docker rm -f db

You can delete the image too (it's big): docker image rm postgres:alpine (Lesson 1).

می‌توانید ایمیج را هم حذف کنید (بزرگ است): docker image rm postgres:alpine (درس ۱).
