Lesson 4 — Open it in the browser درس ۴ — باز کردن در مرورگر

In Lesson 3 nginx was running, but you never saw a web page. You'll find out why, and fix it with -p.

در درس ۳ nginx در حال اجرا بود، ولی هیچ صفحه‌ی وبی ندیدید. می‌فهمید چرا، و با -p درستش می‌کنید.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Try it without -pامتحان بدون -p Doneانجام شد

Start nginx in the background with the name web, exactly like at the end of Lesson 3:

nginx را با نام web در پس‌زمینه اجرا کنید، دقیقاً مثل آخر درس ۳:

bash
docker run -d --name web nginx

Now open http://localhost:8080 in your browser:

حالا http://localhost:8080 را در مرورگرتان باز کنید:

localhost:8080

This site can't be reached

localhost refused to connect.

It doesn't work. A container has its own private network. nginx listens on port 80 inside the container, but nothing connects your PC to it. Even http://localhost:80 fails.

کار نمی‌کند. هر کانتینر شبکه‌ی خصوصی خودش را دارد. nginx روی پورت 80 داخل کانتینر گوش می‌دهد، ولی چیزی کامپیوتر شما را به آن وصل نمی‌کند. حتی http://localhost:80 هم کار نمی‌کند.

Your browserمرورگر شماlocalhost:8080
✕ nothing connectedهیچ اتصالی نیست
Containerکانتینر webnginx on port 80 (inside)nginx روی پورت 80 (داخل)

Stop and delete it, so we can start it again the right way:

متوقفش کنید و حذفش کنید تا بتوانیم درست اجرایش کنیم:

bash
docker stop web
docker rm web

💡 Shortcut: -f (force) does both in one command. It stops the container if it's running, then deletes it:

💡 میان‌بُر: -f (force، یعنی اجباری) هر دو کار را با یک دستور انجام می‌دهد. اگر کانتینر در حال اجرا باشد متوقفش می‌کند و بعد حذفش می‌کند:

bash
docker rm -f web

Use one way or the other, not both.

یکی از این دو روش را استفاده کنید، نه هر دو را.

2 Publish a port with -pمنتشر کردن پورت با -p Doneانجام شد

Same command, plus -p 8080:80:

همان دستور، به‌اضافه‌ی -p 8080:80:

bash
docker run -d --name web -p 8080:80 nginx

-p means publish. It connects a port on your PC to a port inside the container. The order is always your PC first, then the container:

-p یعنی publish (منتشر کردن). یک پورت روی کامپیوتر شما را به یک پورت داخل کانتینر وصل می‌کند. ترتیب همیشه این است: اول کامپیوتر شما، بعد کانتینر:

8080Port on your PC (the host). You choose itپورت روی کامپیوتر شما (host). خودتان انتخابش می‌کنید
80Port inside the container. nginx listens here, so this is fixedپورت داخل کانتینر. nginx اینجا گوش می‌دهد، پس ثابت است
Your browserمرورگر شماlocalhost:8080
-p 8080:80
Containerکانتینر webnginx on port 80nginx روی پورت 80
❓ Error: “port is already allocated”?❓ خطای «port is already allocated»؟
output
docker: Error response from daemon: failed to set up container networking: ... Bind for 0.0.0.0:8080 failed: port is already allocated

Something else on your PC (maybe another container) already uses port 8080. Only one program can use a host port at a time. Delete the new container (docker rm web) and pick another host port, e.g. -p 8081:80, then open localhost:8081.

برنامه‌ی دیگری روی کامپیوتر شما (شاید یک کانتینر دیگر) از پورت 8080 استفاده می‌کند. هر پورت host در هر لحظه فقط مال یک برنامه است. کانتینر جدید را حذف کنید (docker rm web) و یک پورت دیگر انتخاب کنید، مثلاً -p 8081:80، و بعد localhost:8081 را باز کنید.

3 Check the portبررسی پورت Doneانجام شد

List the running containers and look at the PORTS column:

کانتینرهای در حال اجرا را فهرست کنید و به ستون PORTS نگاه کنید:

bash
docker ps
output
CONTAINER ID   IMAGE     COMMAND                  CREATED         STATUS         PORTS                                     NAMES
7ffd259c2bc0   nginx     "/docker-entrypoint.…"   4 seconds ago   Up 2 seconds   0.0.0.0:8080->80/tcp, [::]:8080->80/tcp   web

In Lesson 3 this column said only 80/tcp. Now it says 0.0.0.0:8080->80/tcp: port 8080 on your PC → port 80 in the container. ([::] is the same thing for IPv6.)

در درس ۳ این ستون فقط 80/tcp بود. حالا 0.0.0.0:8080->80/tcp است: پورت 8080 کامپیوتر شما ← پورت 80 کانتینر. ([::] همین است برای IPv6.)

4 Open itباز کردن در مرورگر Doneانجام شد

Open http://localhost:8080 again (or reload the tab):

http://localhost:8080 را دوباره باز کنید (یا تب را reload کنید):

localhost:8080

Welcome to nginx!

If you see this page, nginx is successfully installed and working. …

🎉 This page comes from nginx inside the container.

🎉 این صفحه از nginx داخل کانتینر می‌آید.

❓ Can I check it from the terminal instead?❓ می‌توانم از ترمینال بررسی کنم؟

Yes, with curl, which prints the page's HTML:

بله، با curl که HTML صفحه را چاپ می‌کند:

bash
curl http://localhost:8080
output
<!DOCTYPE html>
<html>
<head>
<title>Welcome to nginx!</title>
...

5 Clean upتمیزکاری Doneانجام شد

Stop the container, then reload the browser tab: the page is gone again.

کانتینر را متوقف کنید و بعد تب مرورگر را reload کنید: صفحه دوباره از دسترس خارج شده.

bash
docker stop web

Delete it, and check it's gone from all containers:

حذفش کنید و بررسی کنید که از همه‌ی کانتینرها حذف شده:

bash
docker rm web
docker ps -a

Remember: we only removed the container. The image is still there. Check it:

یادتان باشد: فقط کانتینر را حذف کردیم. ایمیج هنوز سر جایش است. بررسی کنید:

bash
docker image ls nginx
output
IMAGE          ID             DISK USAGE   CONTENT SIZE   EXTRA
nginx:latest   f9ea18bfa4fa        243MB         66.7MB

🔑 Keep this image. We need it in the next lessons.

🔑 این ایمیج را نگه دارید، چون در درس‌های بعد به آن نیاز داریم.
