Lesson 20 — Copy a whole project درس ۲۰ — کپی کل پروژه

So far you copied files one by one. Real projects have many files, so Dockerfiles usually copy the whole folder with COPY . .. That's convenient, and dangerous: it copies everything, secrets included. You'll see the problem, fix it with .dockerignore, and meet two more instructions: EXPOSE and ENV.

تا الان فایل‌ها را یکی‌یکی کپی کردید. پروژه‌های واقعی فایل‌های زیادی دارند، پس Dockerfileها معمولاً کل پوشه را با COPY . . کپی می‌کنند. راحت است، و خطرناک: همه‌چیز را کپی می‌کند، حتی رمزها را. مشکل را می‌بینید، با .dockerignore درستش می‌کنید و با دو دستور دیگر آشنا می‌شوید: EXPOSE و ENV.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 A small project, with a secretیک پروژه‌ی کوچک، با یک راز Doneانجام شد

Make a project folder called site-app in your home folder and go into it:

یک پوشه‌ی پروژه به نام site-app در پوشه‌ی خانه‌تان بسازید و واردش شوید:

bash
mkdir ~/site-app
cd ~/site-app

Create two pages: index.html with <h1>My site</h1>, and about.html with <h1>About us</h1> (Lesson 6):

دو صفحه بسازید: index.html با <h1>My site</h1>، و about.html با <h1>About us</h1> (درس ۶):

bash
echo '<h1>My site</h1>' > index.html
echo '<h1>About us</h1>' > about.html

Real projects also keep secrets next to the code, like the env file from Lesson 11. Create db.env with nano:

پروژه‌های واقعی رمزها را هم کنار کد نگه می‌دارند، مثل env file درس ۱۱. با nano فایل db.env را بسازید:

db.env
POSTGRES_USER=ali
POSTGRES_PASSWORD=secret
POSTGRES_DB=shop

2 COPY . . and EXPOSECOPY . . و EXPOSE Doneانجام شد

Create Dockerfile with nano:

با nano فایل Dockerfile را بسازید:

Dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY . .
EXPOSE 8000
CMD ["python", "-m", "http.server", "8000"]
COPY . .New: copy everything in this folder (the first .) into the WORKDIR (the second .)جدید: همه‌چیزِ این پوشه (. اول) را به WORKDIR (. دوم) کپی کن
EXPOSE 8000New: document that the app listens on port 8000. It does not publish the port: you still need -p (Lesson 4)جدید: مستند می‌کند که برنامه روی پورت 8000 گوش می‌دهد. پورت را منتشر نمی‌کند: هنوز به -p نیاز دارید (درس ۴)
python -m http.server 8000Python's built-in web server: it serves the files of the current folder on port 8000وب‌سرور داخلی Python: فایل‌های پوشه‌ی فعلی را روی پورت 8000 سرو می‌کند

3 Build and runساخت و اجرا Doneانجام شد

Build the image site-app:

ایمیج site-app را بسازید:

bash
docker build -t site-app .

Run it in the background, named site, with port 8080 on your PC → 8000 in the container:

آن را در پس‌زمینه با نام site اجرا کنید، با پورت 8080 کامپیوتر شما ← 8000 کانتینر:

bash
docker run -d --name site -p 8080:8000 site-app

Open http://localhost:8080:

http://localhost:8080 را باز کنید:

localhost:8080

My site

❓ So what does EXPOSE actually do?❓ پس EXPOSE واقعاً چه کار می‌کند؟

It's a note for people and tools. Run the image without -p and docker ps still shows the port in PORTS, just not published:

یک یادداشت برای آدم‌ها و ابزارهاست. ایمیج را بدون -p اجرا کنید؛ docker ps باز هم پورت را در PORTS نشان می‌دهد، فقط منتشرنشده:

output
PORTS
8000/tcp

That's why nginx showed 80/tcp in Lesson 3: its Dockerfile has EXPOSE 80 (you saw it in docker history, Lesson 16).

برای همین nginx در درس ۳ 80/tcp را نشان داد: Dockerfile آن EXPOSE 80 دارد (آن را در docker history، درس ۱۶ دیدید).

4 What got copied?چه چیزی کپی شد؟ Doneانجام شد

List all files in the image's /app. Run ls -a in a new container from site-app, and delete it afterwards (Lesson 7):

همه‌ی فایل‌های /app در ایمیج را فهرست کنید. ls -a را در یک کانتینر جدید از site-app اجرا کنید و بعد حذفش کنید (درس ۷):

bash
docker run --rm site-app ls -a
output
.
..
Dockerfile
about.html
db.env          # ← your secret, inside the image!
index.html

Worse: the web server serves every file in the folder. Open http://localhost:8080/db.env:

بدتر: وب‌سرور همه‌ی فایل‌های پوشه را سرو می‌کند. http://localhost:8080/db.env را باز کنید:

localhost:8080/db.env

POSTGRES_USER=ali
POSTGRES_PASSWORD=secret
POSTGRES_DB=shop

😱 Anyone who can open your site can read your database password. And anyone who gets your image can read it too, even if you never run it.

😱 هر کسی که بتواند سایت شما را باز کند، رمز دیتابیس شما را می‌خواند. و هر کسی که ایمیج شما را داشته باشد هم می‌تواند آن را بخواند، حتی اگر هیچ‌وقت اجرایش نکنید.

5 Keep files out with .dockerignoreبیرون نگه داشتن فایل‌ها با .dockerignore Doneانجام شد

A file named .dockerignore lists files that docker build must never see, so COPY can't copy them. Create it with nano (the name starts with a dot):

فایلی به نام .dockerignore فایل‌هایی را فهرست می‌کند که docker build هرگز نباید ببیند، پس COPY نمی‌تواند کپی‌شان کند. با nano بسازیدش (نامش با نقطه شروع می‌شود):

.dockerignore
db.env
Dockerfile
.dockerignore

One name per line. Dockerfile and .dockerignore are only needed for building, so they don't belong in the image either.

در هر خط یک نام. Dockerfile و .dockerignore فقط برای ساختن لازم‌اند، پس جایشان در ایمیج هم نیست.

Rebuild the image, delete site in one command, and run it again (step 3):

ایمیج را دوباره بسازید، site را با یک دستور حذف کنید و دوباره اجرایش کنید (قدم ۳):

bash
docker build -t site-app .
docker rm -f site
docker run -d --name site -p 8080:8000 site-app

Check what's inside now (step 4):

ببینید حالا داخلش چیست (قدم ۴):

bash
docker run --rm site-app ls -a
output
.
..
about.html
index.html

Reload localhost:8080/db.env:

localhost:8080/db.env را reload کنید:

localhost:8080/db.env

Error response

Error code: 404 · Message: File not found.

🔑 Whenever you use COPY . ., add a .dockerignore. Put in it: secrets (.env files), .git, caches and anything else the app doesn't need. It's like .gitignore, but for images.

🔑 هر وقت از COPY . . استفاده می‌کنید، یک .dockerignore اضافه کنید. داخلش بگذارید: رمزها (فایل‌های .env)، .git، cacheها و هر چیز دیگری که برنامه لازم ندارد. مثل .gitignore است، ولی برای ایمیج‌ها.

6 Default settings with ENVتنظیمات پیش‌فرض با ENV Doneانجام شد

In Lesson 11 you set environment variables with -e when running. ENV sets one in the image, as a default. Add this line to Dockerfile, right after WORKDIR /app:

در درس ۱۱ متغیرهای محیطی را هنگام اجرا با -e تنظیم کردید. ENV یکی را در ایمیج، به‌عنوان پیش‌فرض، تنظیم می‌کند. این خط را درست بعد از WORKDIR /app به Dockerfile اضافه کنید:

Dockerfile
ENV SITE_NAME="My site"

Rebuild (step 3), then print the variable in a new container:

دوباره بسازید (قدم ۳)، بعد متغیر را در یک کانتینر جدید چاپ کنید:

bash
docker build -t site-app .
bash
docker run --rm site-app printenv SITE_NAME
docker run --rm -e SITE_NAME="Test site" site-app printenv SITE_NAME
output
My site          # the default, from ENV
Test site        # -e replaced it

ENV gives a default that's always there; -e can still change it for one container. You saw image defaults like this in Lesson 11: PostgreSQL's PG_VERSION and PGDATA came from ENV lines in its Dockerfile.

ENV یک مقدار پیش‌فرض می‌دهد که همیشه هست؛ -e هنوز می‌تواند آن را برای یک کانتینر تغییر دهد. پیش‌فرض‌های این‌چنینی را در درس ۱۱ دیدید: PG_VERSION و PGDATA در PostgreSQL از خط‌های ENV در Dockerfile آن آمده بودند.

⚠ Never put passwords in ENV: they'd be baked into the image for anyone to read. Pass them at run time (-e, --env-file) instead.

⚠ هرگز رمز را در ENV نگذارید: داخل ایمیج می‌ماند و هر کسی می‌تواند بخواندش. به‌جایش هنگام اجرا بدهید (-e، --env-file).
