Step 2قدم ۲

COPY . . and EXPOSECOPY . . و EXPOSE

Create Dockerfile with nano:با nano فایل Dockerfile را بسازید:

Dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY . .
EXPOSE 8000
CMD ["python", "-m", "http.server", "8000"]
COPY . .

NEWجدیدCopy everything in this folder (the first .) into the WORKDIR (the second .).همه‌چیزِ این پوشه (. اول) را به WORKDIR (. دوم) کپی کن.

EXPOSE 8000

NEWجدیدDocument that the app listens on port 8000. It does not publish the port: you still need -p (Lesson 4).مستند می‌کند که برنامه روی پورت 8000 گوش می‌دهد. پورت را منتشر نمی‌کند: هنوز به -p نیاز دارید (درس ۴).

python -m http.server 8000

Python's built-in web server: it serves the files of the current folder on port 8000.وب‌سرور داخلی Python: فایل‌های پوشه‌ی فعلی را روی پورت 8000 سرو می‌کند.

Step 3 · A questionقدم ۳ · یک سؤال

❓ So what does EXPOSE do?❓ پس EXPOSE چه کار می‌کند؟

It's a note for people and tools. Run the image without -p and docker ps still shows the port in PORTS, just not published:یک یادداشت برای آدم‌ها و ابزارهاست. ایمیج را بدون -p اجرا کنید؛ docker ps باز هم پورت را در PORTS نشان می‌دهد، فقط منتشرنشده:

WITHOUT -pبدون -p
PORTS 8000/tcp
WITH -p 8080:8000با -p 8080:8000

Only -p really connects a port on your PC (Lesson 4).فقط -p واقعاً یک پورت کامپیوتر شما را وصل می‌کند (درس ۴).

🔑 nginx

That's why nginx showed 80/tcp in Lesson 3: its Dockerfile has EXPOSE 80 (you saw it in docker history, Lesson 16).برای همین nginx در درس ۳ 80/tcp را نشان داد: Dockerfile آن EXPOSE 80 دارد (آن را در docker history، درس ۱۶ دیدید).

Step 5قدم ۵

Keep files out: .dockerignoreبیرون نگه داشتن فایل‌ها: .dockerignore

A file named .dockerignore lists files that docker build must never see, so COPY can't copy them. Create it with nano (the name starts with a dot):فایلی به نام .dockerignore فایل‌هایی را فهرست می‌کند که docker build هرگز نباید ببیند، پس COPY نمی‌تواند کپی‌شان کند. با nano بسازیدش (نامش با نقطه شروع می‌شود):

.dockerignore
db.env
Dockerfile
.dockerignore

One name per line. Dockerfile and .dockerignore are only needed for building, so they don't belong in the image either.در هر خط یک نام. Dockerfile و .dockerignore فقط برای ساختن لازم‌اند، پس جایشان در ایمیج هم نیست.

Whenever you use COPY . ., add a .dockerignore. Put in it: secrets (.env files), .git, caches and anything else the app doesn't need. It's like .gitignore, but for images.هر وقت از COPY . . استفاده می‌کنید، یک .dockerignore اضافه کنید. داخلش بگذارید: رمزها (فایل‌های .env)، .git، cacheها و هر چیز دیگری که برنامه لازم ندارد. مثل .gitignore است، ولی برای ایمیج‌ها.

Step 6قدم ۶

Default settings with ENVتنظیمات پیش‌فرض با ENV

In Lesson 11 you set environment variables with -e when running. ENV sets one in the image, as a default. Add this line right after WORKDIR /app:در درس ۱۱ متغیرهای محیطی را هنگام اجرا با -e تنظیم کردید. ENV یکی را در ایمیج، به‌عنوان پیش‌فرض، تنظیم می‌کند. این خط را درست بعد از WORKDIR /app اضافه کنید:

Dockerfile
FROM python:3.13-slim
WORKDIR /app
ENV SITE_NAME="My site"
COPY . .
EXPOSE 8000
CMD ["python", "-m", "http.server", "8000"]
bash · ~/site-app
docker build -t site-app .
docker run --rm site-app printenv SITE_NAME
My site          # the default, from ENV
docker run --rm -e SITE_NAME="Test site" site-app printenv SITE_NAME
Test site        # -e replaced it
Step 6 · Default vs overrideقدم ۶ · پیش‌فرض و جایگزین

ENV gives a defaultENV یک پیش‌فرض می‌دهد

ENV gives a default that's always there; -e can still change it for one container. You saw image defaults like this in Lesson 11: PostgreSQL's PG_VERSION and PGDATA came from ENV lines in its Dockerfile.ENV یک مقدار پیش‌فرض می‌دهد که همیشه هست؛ -e هنوز می‌تواند آن را برای یک کانتینر تغییر دهد. پیش‌فرض‌های این‌چنینی را در درس ۱۱ دیدید: PG_VERSION و PGDATA در PostgreSQL از خط‌های ENV در Dockerfile آن آمده بودند.

⚠

Never put passwords in ENV: they'd be baked into the image for anyone to read. Pass them at run time (-e, --env-file) instead.هرگز رمز را در ENV نگذارید: داخل ایمیج می‌ماند و هر کسی می‌تواند بخواندش. به‌جایش هنگام اجرا بدهید (-e، --env-file).
