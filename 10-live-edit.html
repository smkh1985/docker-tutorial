Lesson 10 — Edit live with a shared folder درس ۱۰ — ویرایش زنده با یک پوشه‌ی مشترک

In Lesson 8 you used -v to keep data safe. -v has a second superpower: edit files on your PC and the container sees the change right away. You'll use it to work on a web page.

در درس ۸ از -v برای امن نگه داشتن داده‌ها استفاده کردید. -v یک قدرت دوم هم دارد: فایل‌ها را روی کامپیوترتان ویرایش کنید و کانتینر بلافاصله تغییر را می‌بیند. از آن برای کار روی یک صفحه‌ی وب استفاده می‌کنید.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Make a page on your PCساختن یک صفحه روی کامپیوتر Doneانجام شد

These commands run on your PC, not in a container. Make a folder called my-site in your home folder, and put a page in it with echo, like in Lesson 6:

این دستورها روی کامپیوتر خودتان اجرا می‌شوند، نه داخل کانتینر. یک پوشه به نام my-site در پوشه‌ی خانه‌تان بسازید و با echo، مثل درس ۶، یک صفحه در آن بگذارید:

bash
mkdir ~/my-site
echo '<h1>Hello from my PC!</h1>' > ~/my-site/index.html

Check what's in the file:

محتوای فایل را بررسی کنید:

bash
cat ~/my-site/index.html
output
<h1>Hello from my PC!</h1>

2 Mount the folder with -vاتصال پوشه با -v Doneانجام شد

Start nginx named web on localhost:8080, as before, plus -v from Lesson 8. This time share ~/my-site as nginx's page folder:

nginx را با نام web روی localhost:8080 مثل قبل اجرا کنید، به‌اضافه‌ی -v از درس ۸. این بار ~/my-site را به‌عنوان پوشه‌ی صفحه‌های nginx به اشتراک بگذارید:

bash
docker run -d --name web -p 8080:80 -v ~/my-site:/usr/share/nginx/html nginx

As in Lesson 8: your PC first, then the container.

مثل درس ۸: اول کامپیوتر شما، بعد کانتینر.

~/my-siteThe folder on your PCپوشه روی کامپیوتر شما
/usr/share/nginx/htmlThe folder inside the container where nginx looks for pages. You saw it in Lesson 6پوشه‌ی داخل کانتینر که nginx صفحه‌ها را آنجا پیدا می‌کند. در درس ۶ آن را دیدید
Your PCکامپیوتر شما~/my-site/index.html
-v same folder, seen from both sidesیک پوشه، از هر دو طرف
Containerکانتینر web/usr/share/nginx/html/index.html

It's not a copy. The container sees the same folder as your PC.

این یک کپی نیست. کانتینر همان پوشه‌ی کامپیوتر شما را می‌بیند.

❓ The browser shows 403 Forbidden?❓ مرورگر 403 Forbidden نشان می‌دهد؟

You probably mistyped the folder on your PC (e.g. ~/my-sitee). Docker doesn't complain: it silently creates a new, empty folder with that name, owned by root. nginx finds no page there and answers 403.

احتمالاً نام پوشه‌ی کامپیوترتان را اشتباه تایپ کرده‌اید (مثلاً ~/my-sitee). Docker خطا نمی‌دهد: بی‌صدا یک پوشه‌ی جدید و خالی با آن نام می‌سازد که مال root است. nginx آنجا صفحه‌ای پیدا نمی‌کند و 403 جواب می‌دهد.

Fix: delete the container (docker rm -f web), remove the wrong empty folder (sudo rmdir ~/my-sitee), and run again with the right name.

راه‌حل: کانتینر را حذف کنید (docker rm -f web)، پوشه‌ی خالیِ اشتباه را پاک کنید (sudo rmdir ~/my-sitee) و با نام درست دوباره اجرا کنید.

3 Open itباز کردن در مرورگر Doneانجام شد

Open http://localhost:8080:

http://localhost:8080 را باز کنید:

localhost:8080

Hello from my PC!

nginx is serving the file from your PC. No “Welcome to nginx!” this time.

nginx فایل را از کامپیوتر شما سرو می‌کند. این بار خبری از «Welcome to nginx!» نیست.

❓ Where did the original welcome page go?❓ صفحه‌ی خوش‌آمد اصلی کجا رفت؟

Your folder is placed on top of the container's folder and hides what the image had there. Look inside:

پوشه‌ی شما روی پوشه‌ی کانتینر قرار می‌گیرد و چیزی را که ایمیج آنجا داشت پنهان می‌کند. داخلش را ببینید:

bash
docker exec web ls /usr/share/nginx/html
output
index.html

Only your file. 50x.html is hidden. The image itself didn't change: without -v you'd get the welcome page again.

فقط فایل شما. 50x.html پنهان شده. خود ایمیج تغییری نکرده: بدون -v دوباره صفحه‌ی خوش‌آمد را می‌بینید.

4 Edit the page on your PCویرایش صفحه روی کامپیوتر Doneانجام شد

On your PC (no exec, no container), replace the text in ~/my-site/index.html with <h1>Changed on my PC!</h1>:

روی کامپیوتر خودتان (بدون exec، بدون کانتینر)، متن ~/my-site/index.html را با <h1>Changed on my PC!</h1> جایگزین کنید:

bash
echo '<h1>Changed on my PC!</h1>' > ~/my-site/index.html

Reload the browser:

مرورگر را reload کنید:

localhost:8080

Changed on my PC!

The change shows up right away: no restart, no exec. You can also edit the file in any editor on your PC (VS Code, gedit, …).

تغییر بلافاصله دیده می‌شود: بدون ری‌استارت، بدون exec. می‌توانید فایل را با هر ویرایشگری روی کامپیوترتان هم ویرایش کنید (VS Code، gedit و …).

5 Read-only: protect your files with :roفقط‌خواندنی: محافظت از فایل‌ها با :ro Doneانجام شد

nginx only needs to read your page, but right now the container could also change or delete your files. Add :ro (read-only) at the end of -v so it can't.

nginx فقط لازم دارد صفحه‌ی شما را بخواند، ولی الان کانتینر می‌تواند فایل‌های شما را تغییر دهد یا حذف کند. :ro (read-only، فقط‌خواندنی) را به آخر -v اضافه کنید تا نتواند.

Delete web in one command:

web را با یک دستور حذف کنید:

bash
docker rm -f web

Start it again with :ro:

با :ro دوباره اجرایش کنید:

bash
docker run -d --name web -p 8080:80 -v ~/my-site:/usr/share/nginx/html:ro nginx

The page still works. Now go inside web and try to overwrite it with <h1>Hacked!</h1>, like in Lesson 6:

صفحه هنوز کار می‌کند. حالا به داخل web بروید و سعی کنید آن را با <h1>Hacked!</h1> بازنویسی کنید، مثل درس ۶:

bash
docker exec -it web bash
bash · inside
echo '<h1>Hacked!</h1>' > /usr/share/nginx/html/index.html
output
bash: /usr/share/nginx/html/index.html: Read-only file system

✅ Refused. The container can only read the folder. Leave the shell:

✅ رد شد. کانتینر فقط می‌تواند پوشه را بخواند. از شل خارج شوید:

bash · inside
exit

You can still edit the page on your PC, and the browser shows the change as before. :ro only limits the container.

هنوز می‌توانید صفحه را روی کامپیوترتان ویرایش کنید و مرورگر مثل قبل تغییر را نشان می‌دهد. :ro فقط کانتینر را محدود می‌کند.

🔑 If a container only needs to read a folder, mount it with :ro. A bug or an attacker inside the container can't damage your files.

🔑 اگر کانتینری فقط لازم دارد یک پوشه را بخواند، آن را با :ro mount کنید. یک باگ یا مهاجم داخل کانتینر نمی‌تواند به فایل‌های شما آسیب بزند.

6 Clean upتمیزکاری Doneانجام شد

bash
docker rm -f web

🔑 Deleting the container doesn't touch ~/my-site. Keep the folder: we'll use it again in Lesson 17.

🔑 حذف کانتینر به ~/my-site دست نمی‌زند. پوشه را نگه دارید: در درس ۱۷ دوباره از آن استفاده می‌کنیم.
