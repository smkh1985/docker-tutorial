Edit liveویرایش زنده

-v has a second superpower: edit files on your PC and the container sees the change right away. You'll use it to work on a web page.-v یک قدرت دوم هم دارد: فایل‌ها را روی کامپیوترتان ویرایش کنید و کانتینر بلافاصله تغییر را می‌بیند. از آن برای کار روی یک صفحه‌ی وب استفاده می‌کنید.

Press → or Space to startبرای شروع → یا Space را بزنید

Step 1قدم ۱

Make a page on your PCساختن یک صفحه روی کامپیوتر

These commands run on your PC, not in a container. Make a folder called my-site in your home folder, and put a page in it with echo, like in Lesson 6:این دستورها روی کامپیوتر خودتان اجرا می‌شوند، نه داخل کانتینر. یک پوشه به نام my-site در پوشه‌ی خانه‌تان بسازید و با echo، مثل درس ۶، یک صفحه در آن بگذارید:

bash · your PCکامپیوتر شما
mkdir ~/my-site
echo '<h1>Hello from my PC!</h1>' > ~/my-site/index.html
cat ~/my-site/index.html
<h1>Hello from my PC!</h1>
Step 2قدم ۲

Mount the folder with -vاتصال پوشه با ‎-v

bash
docker run -d --name web -p 8080:80 -v ~/my-site:/usr/share/nginx/html nginx

AS IN LESSON 8: YOUR PC FIRSTمثل درس ۸: اول کامپیوتر شما

~/my-site The folder on your PCپوشه روی کامپیوتر شما

/usr/share/nginx/html The folder inside the container where nginx looks for pages. You saw it in Lesson 6پوشه‌ی داخل کانتینر که nginx صفحه‌ها را آنجا پیدا می‌کند. در درس ۶ آن را دیدید

🔑

It's not a copy. The container sees the same folder as your PC.این یک کپی نیست. کانتینر همان پوشه‌ی کامپیوتر شما را می‌بیند.

Step 3قدم ۳

Open localhost:8080localhost:8080 را باز کنید

✅

nginx is serving the file from your PC. No “Welcome to nginx!” this time.nginx فایل را از کامپیوتر شما سرو می‌کند. این بار خبری از «Welcome to nginx!» نیست.

❓ 403 FORBIDDEN?❓ 403 Forbidden؟

You probably mistyped the folder on your PC (e.g. ~/my-sitee). Docker doesn't complain: it silently creates a new, empty folder with that name, owned by root. nginx finds no page there and answers 403.احتمالاً نام پوشه‌ی کامپیوترتان را اشتباه تایپ کرده‌اید (مثلاً ~/my-sitee). Docker خطا نمی‌دهد: بی‌صدا یک پوشه‌ی جدید و خالی با آن نام می‌سازد که مال root است. nginx آنجا صفحه‌ای پیدا نمی‌کند و 403 جواب می‌دهد.

FIXراه‌حل

Delete the container (docker rm -f web), remove the wrong empty folder (sudo rmdir ~/my-sitee), and run again with the right name.کانتینر را حذف کنید (docker rm -f web)، پوشه‌ی خالیِ اشتباه را پاک کنید (sudo rmdir ~/my-sitee) و با نام درست دوباره اجرا کنید.

Step 3 · A questionقدم ۳ · یک سؤال

Where did the welcome page go?صفحه‌ی خوش‌آمد اصلی کجا رفت؟

Your folder is placed on top of the container's folder and hides what the image had there. Look inside:پوشه‌ی شما روی پوشه‌ی کانتینر قرار می‌گیرد و چیزی را که ایمیج آنجا داشت پنهان می‌کند. داخلش را ببینید:

bash
docker exec web ls /usr/share/nginx/html
index.html
🔑

Only your file. 50x.html is hidden. The image itself didn't change: without -v you'd get the welcome page again.فقط فایل شما. 50x.html پنهان شده. خود ایمیج تغییری نکرده: بدون -v دوباره صفحه‌ی خوش‌آمد را می‌بینید.

Step 4قدم ۴

Edit the page on your PCویرایش صفحه روی کامپیوتر

bash · your PCکامپیوتر شما
echo '<h1>Changed on my PC!</h1>' > ~/my-site/index.html
RIGHT AWAYبلافاصله

The change shows up right away: no restart, no exec.تغییر بلافاصله دیده می‌شود: بدون ری‌استارت، بدون exec.

💡

You can also edit the file in any editor on your PC (VS Code, gedit, …).می‌توانید فایل را با هر ویرایشگری روی کامپیوترتان هم ویرایش کنید (VS Code، gedit و …).

Step 5قدم ۵

Protect your files with :roمحافظت از فایل‌ها با ‎:ro

nginx only needs to read your page, but right now the container could also change or delete your files. Add :ro (read-only) at the end of -v so it can't.nginx فقط لازم دارد صفحه‌ی شما را بخواند، ولی الان کانتینر می‌تواند فایل‌های شما را تغییر دهد یا حذف کند. :ro (read-only، فقط‌خواندنی) را به آخر -v اضافه کنید تا نتواند.

bash
docker rm -f web
web
docker run -d --name web -p 8080:80 -v ~/my-site:/usr/share/nginx/html:ro nginx
9e4b1d7a3c6f0e2b8d5a1c4f7e0b3d6a9c2f5e8b1d4a7c0f3e6b9d2a5c8f1e4b

The page still works. :ro only limits the container: it can read the folder, but not change it.صفحه هنوز کار می‌کند. :ro فقط کانتینر را محدود می‌کند: می‌تواند پوشه را بخواند، ولی نمی‌تواند تغییرش دهد.

Step 5 · Test itقدم ۵ · امتحانش کنید

Try to change it from insideسعی کنید از داخل تغییرش دهید

Go inside web and try to overwrite the page with <h1>Hacked!</h1>, like in Lesson 6:به داخل web بروید و سعی کنید صفحه را با <h1>Hacked!</h1> بازنویسی کنید، مثل درس ۶:

bash
docker exec -it web bash
bash · inside webداخل web
echo '<h1>Hacked!</h1>' > /usr/share/nginx/html/index.html
bash: /usr/share/nginx/html/index.html: Read-only file system
exit
✅

Refused. The container can only read the folder.رد شد. کانتینر فقط می‌تواند پوشه را بخواند.

You can still edit the page on your PC, and the browser shows the change as before.هنوز می‌توانید صفحه را روی کامپیوترتان ویرایش کنید و مرورگر مثل قبل تغییر را نشان می‌دهد.

🔑

If a container only needs to read a folder, mount it with :ro. A bug or an attacker inside the container can't damage your files.اگر کانتینری فقط لازم دارد یک پوشه را بخواند، آن را با :ro mount کنید. یک باگ یا مهاجم داخل کانتینر نمی‌تواند به فایل‌های شما آسیب بزند.

Step 6قدم ۶

Clean upتمیزکاری

bash
docker rm -f web
web
🔑

Deleting the container doesn't touch ~/my-site. Keep the folder: we'll use it again in Lesson 17.حذف کانتینر به ~/my-site دست نمی‌زند. پوشه را نگه دارید: در درس ۱۷ دوباره از آن استفاده می‌کنیم.
