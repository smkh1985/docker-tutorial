Networksشبکه‌ها

Real apps are made of several containers: an app and its database. The app must reach the database, ideally by name.برنامه‌های واقعی از چند کانتینر ساخته می‌شوند: یک برنامه و دیتابیسش. برنامه باید به دیتابیس دسترسی داشته باشد، ترجیحاً با نام.

Press → or Space to startبرای شروع → یا Space را بزنید

Step 1قدم ۱

Start a database and an appاجرای یک دیتابیس و یک برنامه

bash
docker run -d --name db -e POSTGRES_PASSWORD=secret postgres:alpine
docker run -d --name adminer -p 8080:8080 adminer

Adminer listens on port 8080 inside its container, so publish it on 8080.Adminer داخل کانتینرش روی پورت 8080 گوش می‌دهد، پس آن را روی 8080 منتشر کنید.

Step 2قدم ۲

Adminer connects to db by nameAdminer با نام به db وصل می‌شود

OPEN localhost:8080 · LOGIN FORMlocalhost:8080 را باز کنید · فرم ورود
SystemPostgreSQL Serverdb← the container's name← نام کانتینر Usernamepostgres(the default user)(کاربر پیش‌فرض) Passwordsecret Databaseleave emptyخالی بگذارید
localhost:8080

Login

SQLSTATE[08006] [7] could not translate host name "db" to address: Name does not resolve

❌ Adminer doesn't know who db is. By default, containers run on Docker's default network, called bridge, where names don't work.❌ Adminer نمی‌داند db کیست. به‌طور پیش‌فرض کانتینرها روی شبکه‌ی پیش‌فرض Docker به نام bridge اجرا می‌شوند، جایی که نام‌ها کار نمی‌کنند.

Step 3قدم ۳

Find db's IP addressپیدا کردن آدرس IP دیتابیس

Every container gets its own IP address on Docker's network. Inspect db and look for "IPAddress" in its long output (like "Mounts" in Lesson 9).هر کانتینر روی شبکه‌ی Docker آدرس IP خودش را می‌گیرد. db را inspect کنید و در خروجی طولانی‌اش دنبال "IPAddress" بگردید (مثل "Mounts" در درس ۹).

bash
docker inspect db
            "Networks": {
                "bridge": {                         # the default network
                    "Gateway": "172.17.0.1",
                    "IPAddress": "172.17.0.5",      # ← db's address (yours will likely differ)
                    ...
localhost:8080

Select database

PostgreSQL » 172.17.0.5 · Logged in as: postgres

Log in with the same form, but put the IP in Server (use yours).با همان فرم وارد شوید، ولی در Server آدرس IP را بنویسید (از آدرس خودتان استفاده کنید).

✅ It works! Containers on the default network can reach each other, just not by name.✅ کار کرد! کانتینرهای روی شبکه‌ی پیش‌فرض می‌توانند به هم دسترسی داشته باشند، فقط نه با نام.

Step 4قدم ۴

But IP addresses changeولی آدرس‌های IP عوض می‌شوند

Containers get recreated all the time: updates, crashes, restarts. Let's see what happens to the IP.کانتینرها مدام دوباره ساخته می‌شوند: به‌روزرسانی، crash، ری‌استارت. ببینیم برای IP چه اتفاقی می‌افتد.

bash
docker rm -f db
docker run -d --name other nginx
docker run -d --name db -e POSTGRES_PASSWORD=secret postgres:alpine
docker inspect db
                    "IPAddress": "172.17.0.7",      # ← a NEW address

other took db's old address. db got a new one.other آدرس قبلی db را گرفت. db یک آدرس جدید گرفت.

Step 4 · Log in with the old IPقدم ۴ · ورود با IP قبلی

The old IP now points to otherIP قبلی حالا به other اشاره می‌کند

localhost:8080

Login

SQLSTATE[08006] [7] connection to server at "172.17.0.5", port 5432 failed: Connection refused

❌ The old IP now points to other, which is not a database. Your app would break every time the IP changes.❌ IP قبلی حالا به other اشاره می‌کند که دیتابیس نیست. برنامه‌ی شما هر بار که IP عوض شود خراب می‌شود.

bash
docker rm -f other

🔑 Never rely on a container's IP address. You want a name that always points to the right container.🔑 هرگز به آدرس IP یک کانتینر تکیه نکنید. چیزی که می‌خواهید یک نام است که همیشه به کانتینر درست اشاره کند.

Step 5قدم ۵

Create your own networkساختن شبکه‌ی خودتان

bash
docker network create mynet
5b4d6d66cf605254a3c5ac34bf922fa6a80f702ce4903c5e642dcad025424499   # the new network's ID
docker network ls
NETWORK ID     NAME      DRIVER    SCOPE
ea6d89a95e5f   bridge    bridge    local      # the default network from step 2
e9fc7164ebde   host      host      local
5b4d6d66cf60   mynet     bridge    local      # yours

Networks have their own list, like images, containers and volumes. You may see more, created by other projects on your PC.شبکه‌ها هم مثل ایمیج‌ها، کانتینرها و volumeها فهرست خودشان را دارند. ممکن است شبکه‌های بیشتری ببینید که پروژه‌های دیگر روی کامپیوتر شما ساخته‌اند.

Step 6قدم ۶

Put both containers on the networkهر دو کانتینر روی شبکه

bash
docker rm -f db adminer
docker run -d --name db --network mynet -e POSTGRES_PASSWORD=secret postgres:alpine
docker run -d --name adminer --network mynet -p 8080:8080 adminer

Start them again, plus --network mynet:دوباره اجرایشان کنید، به‌اضافه‌ی --network mynet:

Step 7قدم ۷

Connect by name againاتصال دوباره با نام

Reload localhost:8080 and log in with exactly the same form as in step 2 (Server: db):localhost:8080 را reload کنید و دقیقاً با همان فرم قدم ۲ وارد شوید (Server: db):

localhost:8080

Select database

PostgreSQL » db · Logged in as: postgres

Database: postgres

✅ You're in! On your own network, Docker lets containers find each other by their names. You are now looking inside the PostgreSQL database through Adminer.✅ وارد شدید! روی شبکه‌ی خودتان، Docker اجازه می‌دهد کانتینرها همدیگر را با نامشان پیدا کنند. حالا از طریق Adminer داخل دیتابیس PostgreSQL را می‌بینید.

Step 7 · Noticeقدم ۷ · دقت کنید

🔑 db has no -p🔑 db هیچ -p ندارد

-p (Lesson 4) is only for reaching a container from your PC. Your browser needs Adminer, so Adminer has -p.-p (درس ۴) فقط برای دسترسی به کانتینر از کامپیوتر شما است. مرورگر شما به Adminer نیاز دارد، پس Adminer -p دارد.

But Adminer reaches db directly over mynet.ولی Adminer مستقیماً از طریق mynet به db می‌رسد.

The database isn't exposed to your PC at all, which is also safer.دیتابیس اصلاً روی کامپیوتر شما باز نیست، که امن‌تر هم هست.

Step 8قدم ۸

Clean upتمیزکاری

bash
docker rm -f db adminer
docker network rm mynet

Like a volume (Lesson 9), a network can't be deleted while containers still use it. You'd get network mynet has active endpoints. That's why the containers go first.مثل volume (درس ۹)، شبکه را تا وقتی کانتینرها از آن استفاده می‌کنند نمی‌شود حذف کرد. خطای network mynet has active endpoints می‌گیرید. برای همین اول کانتینرها حذف می‌شوند.

Summaryخلاصه

🎉 Your app can talk to its database!🎉 برنامه‌ی شما می‌تواند با دیتابیسش صحبت کند!

docker network create NAME

Create a networkساختن یک شبکه

docker run --network NAME …

Start a container on that networkاجرای کانتینر روی آن شبکه

docker network ls

List networksفهرست شبکه‌ها

docker network rm NAME

Delete a network (not while containers use it)حذف شبکه (نه وقتی کانتینرها از آن استفاده می‌کنند)

Container name = address. On the same network, containers reach each other by name; no -p needed.نام کانتینر = آدرس. روی یک شبکه، کانتینرها با نام به هم دسترسی دارند؛ -p لازم نیست.
