Lesson 13 — Networks: containers talking to each other درس ۱۳ — شبکه‌ها: صحبت کانتینرها با هم

Real apps are made of several containers: an app and its database. The app must reach the database, ideally by name. You'll run a PostgreSQL database (Lesson 11) and Adminer, a ready-made web app for looking inside databases, and connect them.

برنامه‌های واقعی از چند کانتینر ساخته می‌شوند: یک برنامه و دیتابیسش. برنامه باید به دیتابیس دسترسی داشته باشد، ترجیحاً با نام. یک دیتابیس PostgreSQL (درس ۱۱) و Adminer را اجرا می‌کنید (یک برنامه‌ی وب آماده برای دیدن داخل دیتابیس‌ها) و آن‌ها را به هم وصل می‌کنید.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Start a database and an appاجرای یک دیتابیس و یک برنامه Doneانجام شد

Start PostgreSQL in the background, named db, with the password secret (Lesson 11):

PostgreSQL را در پس‌زمینه با نام db و رمز secret اجرا کنید (درس ۱۱):

bash
docker run -d --name db -e POSTGRES_PASSWORD=secret postgres:alpine

Start Adminer, named adminer. It listens on port 8080 inside its container, so publish it on 8080:

Adminer را با نام adminer اجرا کنید. داخل کانتینرش روی پورت 8080 گوش می‌دهد، پس آن را روی 8080 منتشر کنید:

bash
docker run -d --name adminer -p 8080:8080 adminer

http://localhost:8080 را باز کنید و فرم ورود را پر کنید:

Click Login:

روی Login کلیک کنید:

SQLSTATE[08006] [7] could not translate host name "db" to address: Name does not resolve

❌ Adminer doesn't know who db is. By default, containers run on Docker's default network, called bridge, where names don't work.

❌ Adminer نمی‌داند db کیست. به‌طور پیش‌فرض کانتینرها روی شبکه‌ی پیش‌فرض Docker به نام bridge اجرا می‌شوند، جایی که نام‌ها کار نمی‌کنند.

3 Find db's IP address, and connect by IPپیدا کردن آدرس IP دیتابیس و اتصال با IP Doneانجام شد

Every container gets its own IP address on Docker's network. Find db's: inspect the container and look for "IPAddress" in its long output (like "Mounts" in Lesson 9):

هر کانتینر روی شبکه‌ی Docker آدرس IP خودش را می‌گیرد. آدرس db را پیدا کنید: کانتینر را inspect کنید و در خروجی طولانی‌اش دنبال "IPAddress" بگردید (مثل "Mounts" در درس ۹):

bash
docker inspect db
output
            "Networks": {
                "bridge": {                         # the default network
                    "Gateway": "172.17.0.1",
                    "IPAddress": "172.17.0.5",      # ← db's address (yours will likely differ)
                    ...

Back in Adminer, log in with the same form, but this time put the IP in Server (e.g. 172.17.0.5, use yours):

به Adminer برگردید و با همان فرم وارد شوید، ولی این بار در Server آدرس IP را بنویسید (مثلاً 172.17.0.5؛ از آدرس خودتان استفاده کنید):

localhost:8080

Select database

PostgreSQL » 172.17.0.5 · Logged in as: postgres

✅ It works! Containers on the default network can reach each other, just not by name.

✅ کار کرد! کانتینرهای روی شبکه‌ی پیش‌فرض می‌توانند به هم دسترسی داشته باشند، فقط نه با نام.

Checklistچک‌لیست

4 But IP addresses changeولی آدرس‌های IP عوض می‌شوند Doneانجام شد

Containers get recreated all the time: updates, crashes, restarts. Let's see what happens to the IP. Delete db in one command:

کانتینرها مدام دوباره ساخته می‌شوند: به‌روزرسانی، crash، ری‌استارت. ببینیم برای IP چه اتفاقی می‌افتد. db را با یک دستور حذف کنید:

bash
docker rm -f db

Meanwhile another container starts. Run any nginx in the background, named other:

در همین حین یک کانتینر دیگر اجرا می‌شود. یک nginx در پس‌زمینه با نام other اجرا کنید:

bash
docker run -d --name other nginx

Now start db again, exactly like in step 1, and look at its "IPAddress" again:

حالا db را دقیقاً مثل قدم ۱ دوباره اجرا کنید و دوباره به "IPAddress" آن نگاه کنید:

bash
docker run -d --name db -e POSTGRES_PASSWORD=secret postgres:alpine
docker inspect db
output
                    "IPAddress": "172.17.0.7",      # ← a NEW address

other took db's old address. Log in to Adminer with the old IP:

other آدرس قبلی db را گرفت. با IP قبلی در Adminer وارد شوید:

localhost:8080

Login

SQLSTATE[08006] [7] connection to server at "172.17.0.5", port 5432 failed: Connection refused

❌ The old IP now points to other, which is not a database. Your app would break every time the IP changes. Delete other:

❌ IP قبلی حالا به other اشاره می‌کند که دیتابیس نیست. برنامه‌ی شما هر بار که IP عوض شود خراب می‌شود. other را حذف کنید:

bash
docker rm -f other

🔑 Never rely on a container's IP address. You want a name that always points to the right container.

🔑 هرگز به آدرس IP یک کانتینر تکیه نکنید. چیزی که می‌خواهید یک نام است که همیشه به کانتینر درست اشاره کند.

5 Create your own networkساختن شبکه‌ی خودتان Doneانجام شد

bash
docker network create mynet
output
5b4d6d66cf605254a3c5ac34bf922fa6a80f702ce4903c5e642dcad025424499   # the new network's ID

Networks have their own list, like images, containers and volumes:

شبکه‌ها هم مثل ایمیج‌ها، کانتینرها و volumeها فهرست خودشان را دارند:

bash
docker network ls
output
NETWORK ID     NAME      DRIVER    SCOPE
ea6d89a95e5f   bridge    bridge    local      # the default network from step 2
e9fc7164ebde   host      host      local
5b4d6d66cf60   mynet     bridge    local      # yours
e1ecff10f049   none      null      local

You may see more, created by other projects on your PC.

ممکن است شبکه‌های بیشتری ببینید که پروژه‌های دیگر روی کامپیوتر شما ساخته‌اند.

6 Put both containers on the networkقرار دادن هر دو کانتینر روی شبکه Doneانجام شد

Delete both containers with one command:

هر دو کانتینر را با یک دستور حذف کنید:

bash
docker rm -f db adminer

Start them again, plus --network mynet:

دوباره اجرایشان کنید، به‌اضافه‌ی --network mynet:

bash
docker run -d --name db --network mynet -e POSTGRES_PASSWORD=secret postgres:alpine
docker run -d --name adminer --network mynet -p 8080:8080 adminer

7 Connect againاتصال دوباره Doneانجام شد

Reload localhost:8080 and log in with exactly the same form as in step 2 (Server: db):

localhost:8080 را reload کنید و دقیقاً با همان فرم قدم ۲ وارد شوید (Server: db):

localhost:8080

Select database

PostgreSQL » db · Logged in as: postgres

Database: postgres

✅ You're in! On your own network, Docker lets containers find each other by their names. You are now looking inside the PostgreSQL database through Adminer.

✅ وارد شدید! روی شبکه‌ی خودتان، Docker اجازه می‌دهد کانتینرها همدیگر را با نامشان پیدا کنند. حالا از طریق Adminer داخل دیتابیس PostgreSQL را می‌بینید.

🔑 Notice: db has no -p! -p (Lesson 4) is only for reaching a container from your PC. Your browser needs Adminer, so Adminer has -p. But Adminer reaches db directly over mynet. The database isn't exposed to your PC at all, which is also safer.

🔑 دقت کنید: db -p ندارد! -p (درس ۴) فقط برای دسترسی به کانتینر از کامپیوتر شما است. مرورگر شما به Adminer نیاز دارد، پس Adminer -p دارد. ولی Adminer مستقیماً از طریق mynet به db می‌رسد. دیتابیس اصلاً روی کامپیوتر شما باز نیست، که امن‌تر هم هست.

8 Clean upتمیزکاری Doneانجام شد

Delete both containers first, with one command:

اول هر دو کانتینر را با یک دستور حذف کنید:

bash
docker rm -f db adminer

Then delete the network:

بعد شبکه را حذف کنید:

bash
docker network rm mynet

Like a volume (Lesson 9), a network can't be deleted while containers still use it. You'd get network mynet has active endpoints. That's why the containers go first.

مثل volume (درس ۹)، شبکه را تا وقتی کانتینرها از آن استفاده می‌کنند نمی‌شود حذف کرد. خطای network mynet has active endpoints می‌گیرید. برای همین اول کانتینرها حذف می‌شوند.
