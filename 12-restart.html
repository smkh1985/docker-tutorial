Lesson 12 — Restart policies درس ۱۲ — سیاست‌های راه‌اندازی مجدد

Programs crash, and computers reboot. By default, a container that stops stays stopped: your database or website is down until you notice. A restart policy tells Docker to bring it back by itself.

برنامه‌ها crash می‌کنند و کامپیوترها ری‌استارت می‌شوند. به‌طور پیش‌فرض، کانتینری که متوقف شود متوقف می‌ماند: دیتابیس یا وب‌سایت شما تا وقتی متوجه نشوید از کار افتاده است. یک سیاست راه‌اندازی مجدد (restart policy) به Docker می‌گوید خودش آن را برگرداند.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 A program that crashesبرنامه‌ای که crash می‌کند Doneانجام شد

Let's fake a crashing app. This container prints started, waits 3 seconds, then quits with an error (code 1):

بیایید یک برنامه‌ی crash‌کننده بسازیم. این کانتینر started را چاپ می‌کند، ۳ ثانیه صبر می‌کند و بعد با خطا (کد 1) تمام می‌شود:

bash
docker run -d --name crashy alpine sh -c "echo started; sleep 3; exit 1"

The part after the image is the command to run (Lesson 7). sh -c "…" runs several commands, separated by ;.

بخش بعد از ایمیج دستوری است که اجرا می‌شود (درس ۷). sh -c "…" چند دستور را که با ; جدا شده‌اند اجرا می‌کند.

Wait a few seconds, then list all containers:

چند ثانیه صبر کنید، بعد همه‌ی کانتینرها را فهرست کنید:

bash
docker ps -a
output
NAMES     STATUS                     # other columns left out
crashy    Exited (1) 3 seconds ago

It crashed, and it stays crashed. Its log shows it started only once:

crash کرد و crash‌شده می‌ماند. لاگش نشان می‌دهد فقط یک بار شروع شده:

bash
docker logs crashy
output
started

Delete it:

حذفش کنید:

bash
docker rm crashy

2 Add --restartاضافه کردن --restart Doneانجام شد

Same container, plus --restart unless-stopped:

همان کانتینر، به‌اضافه‌ی --restart unless-stopped:

bash
docker run -d --name crashy --restart unless-stopped alpine sh -c "echo started; sleep 3; exit 1"

Wait about 20 seconds, then read the log again:

حدود ۲۰ ثانیه صبر کنید، بعد دوباره لاگ را بخوانید:

bash
docker logs crashy
output
started
started
started
started
started

✅ Every time it crashed, Docker started it again. Each restart waits a bit longer than the previous one, so a broken app doesn't restart thousands of times. Check its status:

✅ هر بار که crash کرد، Docker دوباره راهش انداخت. هر راه‌اندازی مجدد کمی بیشتر از قبلی صبر می‌کند، تا یک برنامه‌ی خراب هزاران بار راه نیفتد. وضعیتش را بررسی کنید:

bash
docker ps
output
NAMES     STATUS          # other columns left out
crashy    Up 3 seconds

3 You stop it: does it come back?خودتان متوقفش کنید: برمی‌گردد؟ Doneانجام شد

Stop crashy yourself (it may take up to 10 seconds):

crashy را خودتان متوقف کنید (ممکن است تا ۱۰ ثانیه طول بکشد):

bash
docker stop crashy

Wait a few seconds, then list all containers:

چند ثانیه صبر کنید، بعد همه‌ی کانتینرها را فهرست کنید:

bash
docker ps -a
output
NAMES     STATUS                     # other columns left out
crashy    Exited (1) 8 seconds ago

It stays stopped. That's the unless-stopped part: Docker restarts it after crashes, but respects your docker stop.

متوقف می‌ماند. این همان بخش unless-stopped است: Docker بعد از crash آن را دوباره راه می‌اندازد، ولی به docker stop شما احترام می‌گذارد.

Delete it:

حذفش کنید:

bash
docker rm crashy

4 Which policy should I use?از کدام سیاست استفاده کنم؟ Doneانجام شد

--restart After a crashبعد از crash After the PC rebootsبعد از ری‌استارت کامپیوتر
no (default)(پیش‌فرض)❌❌
unless-stopped✅✅ unless you had stopped it✅ مگر اینکه خودتان متوقفش کرده باشید
always✅✅ even if you had stopped it✅ حتی اگر خودتان متوقفش کرده باشید

We can't reboot your PC in a lesson, but after a reboot Docker starts again and brings back every container whose policy says so.

در یک درس نمی‌توانیم کامپیوتر شما را ری‌استارت کنیم، ولی بعد از ری‌استارت، Docker دوباره اجرا می‌شود و هر کانتینری را که سیاستش بگوید برمی‌گرداند.

🔑 For anything that should always be running, like a database or a web server, use --restart unless-stopped. For example, the database from Lesson 11:

🔑 برای هر چیزی که باید همیشه در حال اجرا باشد، مثل یک دیتابیس یا وب‌سرور، از --restart unless-stopped استفاده کنید. مثلاً دیتابیس درس ۱۱:

just look, don't run
docker run -d --name db --restart unless-stopped --env-file db.env postgres:alpine
