Before we startقبل از شروع

Containers are temporaryکانتینرها موقتی هستند

Containers are ephemeral (temporary): when you delete a container, everything inside it is deleted too. You saw this in Lesson 6.کانتینرها موقتی هستند (ephemeral): وقتی کانتینری را حذف می‌کنید، همه‌ی محتوای داخلش هم حذف می‌شود. این را در درس ۶ دیدید.

But some files must survive:ولی بعضی فایل‌ها باید باقی بمانند:

🗄

a databaseیک دیتابیس

📊

your program's outputsخروجی‌های برنامه

📤

uploaded filesفایل‌های آپلودشده

📦

build artifactsآرتیفکت‌ها

Step 1قدم ۱

Save a “database” inside a containerذخیره‌ی یک «دیتابیس» داخل کانتینر

bash
docker run -d --name app nginx
a3c9e1f27b54d0e6c8a2f4b19d7e3c5a0b8f6e2d4c1a9b7e5f3d2c0a8b6e4f2d
docker exec -it app bash
root@a3c9e1f27b54:/#
mkdir /data
echo "Ali, balance: 100" > /data/db.txt
cat /data/db.txt
Ali, balance: 100
exit

Pretend the file /data/db.txt is your app's database: create the folder, save a record, and read it back.فرض کنید فایل /data/db.txt دیتابیس برنامه‌ی شماست: پوشه را بسازید، یک رکورد ذخیره کنید و دوباره بخوانیدش.

Step 2قدم ۲

Delete the container: is the database still there?حذف کانتینر: دیتابیس هنوز هست؟

bash
docker rm -f app
app
docker run -d --name app nginx
e8b14f0c6d2a9e7b3f5c1d8a0e6b4f2c9d7a5e3b1f0c8d6a4e2b0f9c7d5a3e1b
docker exec app cat /data/db.txt
cat: /data/db.txt: No such file or directory

💡 Look with just one command. Without -it, docker exec runs it, prints the result, and you stay on your PC.💡 فقط با یک دستور نگاه کنید. بدون -it، docker exec آن را اجرا می‌کند، نتیجه را چاپ می‌کند و شما روی کامپیوتر خودتان می‌مانید.

❌ The database is gone. It lived inside the old container, and was deleted with it. Imagine this was your real users' data! (Delete this container too: docker rm -f app.)❌ دیتابیس از بین رفت. داخل کانتینر قبلی بود و همراه آن حذف شد. تصور کنید این داده‌های واقعی کاربرانتان بود! (این کانتینر را هم حذف کنید: docker rm -f app.)

Step 3قدم ۳

Add a volume with -vاضافه کردن volume با ⁦-v⁩

The fix: keep /data outside the container, in a folder on your PC. Make that folder, then start app again, plus -v:راه‌حل: /data را بیرون از کانتینر، در یک پوشه روی کامپیوترتان نگه دارید. آن پوشه را بسازید، بعد app را دوباره اجرا کنید، به‌اضافه‌ی -v:

bash
mkdir ~/my-data
docker run -d --name app -v ~/my-data:/data nginx
7d2e4b91c0a3f5e8d6c4b2a0f9e7d5c3b1a8f6e4d2c0b9a7f5e3d1c8b6a4f2e0
-v ~/my-datathe folder on your PCپوشه روی کامپیوتر شما:/datainside the containerداخل کانتینر

-v means volume. It works like -p, but for folders: your PC first, then the container.-v یعنی volume. مثل -p کار می‌کند ولی برای پوشه‌ها: اول کامپیوتر شما، بعد کانتینر.

🔑 It's not a copy: the container reads and writes your PC's folder directly. (Sharing a folder from your PC like this is called a bind mount.)🔑 این یک کپی نیست: کانتینر مستقیماً در پوشه‌ی کامپیوتر شما می‌خواند و می‌نویسد. (به اشتراک گذاشتن یک پوشه‌ی کامپیوتر به این شکل bind mount نام دارد.)

Step 4قدم ۴

Save the database againذخیره‌ی دوباره‌ی دیتابیس

bash
docker exec -it app bash
root@7d2e4b91c0a3:/#
echo "Ali, balance: 100" > /data/db.txt
exit
cat ~/my-data/db.txt
Ali, balance: 100   # on your PC, outside any container

Save the same record in /data/db.txt, and leave. (/data already exists now, so no mkdir.)همان رکورد را در /data/db.txt ذخیره کنید و خارج شوید. (/data حالا وجود دارد، پس mkdir لازم نیست.)

✅ Now look on your PC: the container wrote the database into your PC's folder.✅ حالا روی کامپیوتر خودتان نگاه کنید: کانتینر دیتابیس را در پوشه‌ی کامپیوتر شما نوشت.

❓ CAN'T EDIT db.txt ON MY PC?نمی‌توانم db.txt را ویرایش کنم؟

Inside the container you were root, so the file belongs to root on your PC too (ls -l ~/my-data shows it). Your normal user can read it, but changing it gives permission denied. Use sudo if you really need to edit it.داخل کانتینر شما root بودید، پس فایل روی کامپیوترتان هم مال root است (ls -l ~/my-data این را نشان می‌دهد). کاربر معمولی شما می‌تواند آن را بخواند ولی تغییرش خطای permission denied می‌دهد. اگر واقعاً لازم است ویرایشش کنید، از sudo استفاده کنید.

Step 5قدم ۵

Delete the container again: does the database survive?حذف دوباره‌ی کانتینر: دیتابیس باقی می‌ماند؟

bash
docker rm -f app
app
docker run -d --name app -v ~/my-data:/data nginx
2f9c7e5a3b1d0f8e6c4a2b9d7f5e3c1a0b8d6f4e2c9a7b5d3f1e0c8a6b4d2f9c
docker exec app cat /data/db.txt
Ali, balance: 100

✅ The database survived! The new container found it, because it was never inside the container: it's on your PC.✅ دیتابیس باقی ماند! کانتینر جدید آن را پیدا کرد، چون هیچ‌وقت داخل کانتینر نبود: روی کامپیوتر شماست.

Step 5 · Compareقدم ۵ · مقایسه

Containers are temporary; volumes are notکانتینرها موقتی هستند؛ volumeها نه

Without -v (step 2)بدون -v (قدم ۲)With -v (step 5)با -v (قدم ۵)
db.txt livesdb.txt کجاستinside the containerداخل کانتینرon your PCروی کامپیوتر شما
After docker rmبعد از docker rm❌ goneاز بین رفت✅ keptباقی ماند
🔑

Containers are temporary; volumes are not. Put anything you want to keep (databases, outputs, artifacts) in a volume.کانتینرها موقتی هستند؛ volumeها نه. هر چیزی را که می‌خواهید نگه دارید (دیتابیس‌ها، خروجی‌ها، آرتیفکت‌ها) در یک volume بگذارید.

Step 6قدم ۶

Clean upتمیزکاری

bash
docker rm -f app
app

Deleting the container doesn't touch ~/my-data: db.txt is still on your PC.حذف کانتینر به ~/my-data دست نمی‌زند: db.txt هنوز روی کامپیوتر شماست.

💡 Can Docker manage the storage folder for you, instead of a PC folder? Yes: that's a named volume, the next lesson.💡 Docker می‌تواند به‌جای پوشه‌ی کامپیوتر، خودش محل ذخیره‌سازی را مدیریت کند؟ بله: اسمش named volume است، موضوع درس بعد.
