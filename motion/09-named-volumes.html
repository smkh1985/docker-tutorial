Start Redis, count visitsRedis را اجرا کنید، بازدیدها را بشمارید

COUNT VISITSشمردن بازدیدها

Imagine every page visit on your website adds 1 to a counter in the database. Run this three times.فرض کنید هر بازدید از وب‌سایت شما یک واحد به یک شمارنده در دیتابیس اضافه می‌کند. این را سه بار اجرا کنید.

redis-cli: Redis's command-line tool, inside the image.
INCR visits: increment, add 1 to visits and print it. Starts from 0.redis-cli: ابزار خط فرمان Redis، داخل ایمیج.
INCR visits: Increment، یک واحد به visits اضافه کن و چاپش کن. از 0 شروع می‌کند.

Step 4 · Find the folderقدم ۴ · پیدا کردن پوشه

Where does Redis save its data?Redis داده‌هایش را کجا ذخیره می‌کند؟

To keep the data, the volume must go on the folder where Redis saves it. Ask Redis (the cache from step 3 is still running):برای نگه داشتن داده‌ها باید volume را روی پوشه‌ای بگذاریم که Redis داده‌ها را آنجا ذخیره می‌کند. از خود Redis بپرسید (cache از قدم ۳ هنوز در حال اجراست):

bash
docker exec cache redis-cli CONFIG GET dir
dir
/data
🔑

Redis saves its data in /data, in a file called dump.rdb. The official Redis image sets this up, and its page on Docker Hub says so.Redis داده‌هایش را در /data ذخیره می‌کند، در فایلی به نام dump.rdb. ایمیج رسمی Redis این را تنظیم کرده و صفحه‌اش در Docker Hub هم همین را می‌گوید.

💡

Every database keeps its data in its own folder, e.g. PostgreSQL under /var/lib/postgresql. Check the image's page on Docker Hub. A volume on the wrong folder saves nothing.هر دیتابیس داده‌هایش را در پوشه‌ی خودش نگه می‌دارد، مثلاً PostgreSQL زیر /var/lib/postgresql. صفحه‌ی ایمیج را در Docker Hub ببینید. volume روی پوشه‌ی اشتباه هیچ چیزی را نگه نمی‌دارد.

Step 4 · Add a named volumeقدم ۴ · اضافه کردن named volume

Put a named volume on /dataیک named volume روی ‎/data بگذارید

bash
docker stop cache
cache
docker rm cache
cache
docker run -d --name cache -v redisdata:/data redis:alpine
8c2d7e1f4a9b3c6d0e5f8a2b7c1d4e9f3a6b0c5d8e2f7a1b4c9d3e6f0a5b8c2d
docker exec cache redis-cli INCR visits
1
2
3
A NAME, NOT A PATHیک نام، نه مسیر

Before the : there's a name (redisdata), not a path. No mkdir needed: if the volume doesn't exist yet, Docker creates it.قبل از : یک نام (redisdata) آمده، نه مسیر. mkdir لازم نیست: اگر volume هنوز وجود نداشته باشد، Docker آن را می‌سازد.

💡

/data already exists in the image. The volume does not go inside it (there is no /data/data): it takes the place of /data.پوشه‌ی /data از قبل در ایمیج وجود دارد. volume داخل آن نمی‌رود (/data/data نداریم): بلکه جای /data را می‌گیرد.

OWN LISTفهرست جدا

Named volumes have their own list, like images and containers. You may see other volumes too, created by other projects on your PC.named volumeها هم مثل ایمیج‌ها و کانتینرها فهرست خودشان را دارند. ممکن است volumeهای دیگری هم ببینید که پروژه‌های دیگر روی کامپیوتر شما ساخته‌اند.

❓ ~/my-data

Is Lesson 8's folder in this list? No. It lists only volumes that Docker manages. A bind mount is just a folder on your PC.پوشه‌ی درس ۸ در این فهرست هست؟ نه. فقط volumeهایی را فهرست می‌کند که Docker مدیریت می‌کند. bind mount فقط یک پوشه روی کامپیوتر شماست.

It lives in Docker's own storage folder. You don't open it yourself: you use it through containers, and Docker takes care of it.در پوشه‌ی ذخیره‌سازی خود Docker است. خودتان بازش نمی‌کنید: از طریق کانتینرها از آن استفاده می‌کنید و Docker مراقبش است.

Step 6قدم ۶

Recreate again: does it remember now?ساخت دوباره: حالا یادش می‌ماند؟

bash
docker stop cache
cache
docker rm cache
cache
docker run -d --name cache -v redisdata:/data redis:alpine
f3a9c1e7b5d2084c6e1a9f3b7d5c2e8a0f4b6d1c9e3a7f5b2d8c0e6a4f1b9d3c
docker exec cache redis-cli INCR visits
4
docker exec cache ls -l /data
-rw-------    1 redis    redis          104 Oct 10 10:48 dump.rdb

That's the database file Redis wrote when you stopped the old container.این همان فایل دیتابیس است که Redis هنگام متوقف کردن کانتینر قبلی نوشت.

When you ran docker stop, Redis saved its data to /data, which is the volume. The volume outlived the container.وقتی docker stop زدید، Redis داده‌هایش را در /data ذخیره کرد، که همان volume است. volume بیشتر از کانتینر عمر کرد.

without a volume (step 3): ❌ 1
with -v redisdata:/data: ✅ 4بدون volume (قدم ۳): ❌ 1

Step 6 · Carefulقدم ۶ · مراقب باشید

⚠ Stop databases cleanly⚠ دیتابیس‌ها را با آرامش متوقف کنید

Redis keeps data in memory and saves it to disk when it stops. A volume only keeps what is written to disk.Redis داده‌ها را در حافظه نگه می‌دارد و وقتی متوقف می‌شود روی دیسک ذخیره‌شان می‌کند. volume فقط چیزی را نگه می‌دارد که روی دیسک نوشته شده باشد.

We tried it: counted to 5, ran rm -f, and the new container had 3. The last visits were lost, even with a volume. Before the first docker stop, /data is still empty.امتحانش کردیم: تا 5 شمردیم، rm -f زدیم، و کانتینر جدید 3 داشت. آخرین بازدیدها از دست رفتند، حتی با volume. قبل از اولین docker stop، پوشه‌ی /data هنوز خالی است.

🔑

Redis also saves by itself from time to time, but you can't count on the latest changes being saved. Use docker stop first.Redis هر از گاهی خودش هم ذخیره می‌کند، اما نمی‌شود روی ذخیره شدن آخرین تغییرات حساب کرد. اول از docker stop استفاده کنید.

Step 7قدم ۷

Delete the volumeحذف volume

bash
docker volume rm redisdata
Error response from daemon: remove redisdata: volume is in use - [73dbe5f93b9c…]
docker stop cache
cache
docker rm cache
cache
docker volume rm redisdata
redisdata
docker volume ls
DRIVER    VOLUME NAME

Docker refuses: cache is still using it. This protects you from deleting a database under a running app.Docker قبول نمی‌کند: cache هنوز از آن استفاده می‌کند. این از شما محافظت می‌کند تا دیتابیس را از زیر پای یک برنامه‌ی در حال اجرا پاک نکنید.

⚠

docker volume rm deletes the data for good. No undo. Double-check the name.docker volume rm داده‌ها را برای همیشه حذف می‌کند. راه برگشتی نیست. نام را دوباره بررسی کنید.
