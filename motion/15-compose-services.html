Step 1قدم ۱

Project folder and env fileپوشه‌ی پروژه و env file

bash
mkdir ~/compose-db
cd ~/compose-db
db.env
POSTGRES_USER=ali
POSTGRES_PASSWORD=secret
POSTGRES_DB=shop

Create db.env with nano, with the same three settings as in Lesson 11.با nano فایل db.env را با همان سه تنظیم درس ۱۱ بسازید.

Step 2قدم ۲

Write compose.yamlنوشتن compose.yaml

compose.yaml
services:
db:
image: postgres:alpine
env_file: db.env
volumes:
- pgdata:/var/lib/postgresql
adminer:
image: adminer
ports:
- "8080:8080"
volumes:
pgdata:

Create compose.yaml with nano in the same folder (mind the spaces). Press → to read it line by line.با nano فایل compose.yaml را در همان پوشه بسازید (به فاصله‌ها دقت کنید). → را بزنید تا خط به خط بخوانیدش.

db:adminer:

Two services, like --name db and --name adminer.دو سرویس، مثل --name db و --name adminer.

env_file: db.env↔--env-file db.env

Same as --env-file (Lesson 11).معادل --env-file (درس ۱۱).

- pgdata:/var/lib/postgresql

A named volume on PostgreSQL's data folder, like -v (Lesson 9).یک named volume روی پوشه‌ی داده‌ی PostgreSQL، مثل -v (درس ۹).

- "8080:8080"↔-p 8080:8080

Only Adminer, for your browser.فقط Adminer، برای مرورگر شما.

volumes: pgdata:

At the bottom, without indentation: declare the named volume. Compose requires this.در پایین، بدون تورفتگی: named volume را اعلام می‌کند. Compose این را لازم دارد.

NO NETWORK?شبکه نیست؟

Compose creates one for the project and puts every service on it (Lesson 14).Compose یکی برای پروژه می‌سازد و همه‌ی سرویس‌ها را رویش می‌گذارد (درس ۱۴).

Step 3قدم ۳

Start everythingاجرای همه‌چیز

bash
docker compose up -d
[+] up 4/4
 ✔ Network compose-db_default     Created
 ✔ Volume compose-db_pgdata       Created
 ✔ Container compose-db-adminer-1 Started
 ✔ Container compose-db-db-1      Started

One command, four things: a network, a volume and two containers.یک دستور، چهار چیز: یک شبکه، یک volume و دو کانتینر.

Step 3 · Checkقدم ۳ · بررسی

Both are Upهر دو Up هستند

bash
docker compose ps
NAME                   SERVICE   STATUS         PORTS
compose-db-adminer-1   adminer   Up 6 seconds   0.0.0.0:8080->8080/tcp, [::]:8080->8080/tcp
compose-db-db-1        db        Up 7 seconds   5432/tcp
db

db shows only 5432/tcp: PostgreSQL's port, not published to your PC (Lesson 13).db فقط 5432/tcp را نشان می‌دهد: پورت PostgreSQL، که روی کامپیوتر شما منتشر نشده (درس ۱۳).

adminer

Adminer is published on 8080, for your browser.Adminer روی 8080 منتشر شده، برای مرورگر شما.

Step 5قدم ۵

Save some dataذخیره‌ی مقداری داده

Create a table products and add one product, using psql (Lesson 11) inside the db service:با psql (درس ۱۱) داخل سرویس db، یک جدول products بسازید و یک محصول اضافه کنید:

bash
docker compose exec db psql -U ali -d shop -c "CREATE TABLE products (name text);" -c "INSERT INTO products VALUES ('coffee');"
CREATE TABLE
INSERT 0 1

docker compose exec is like docker exec, but you use the service name (db). Reload Adminer: the table products is there, with coffee in it.docker compose exec مثل docker exec است، ولی از نام سرویس (db) استفاده می‌کنید. Adminer را reload کنید: جدول products آنجاست و coffee داخلش.

Step 6قدم ۶

down, then up: is the data still there?down و دوباره up: داده‌ها هنوز هستند؟

bash
docker compose down
docker volume ls
DRIVER    VOLUME NAME
local     compose-db_pgdata
docker compose up -d
docker compose exec db psql -U ali -d shop -c "SELECT * FROM products;"
  name
--------
 coffee
(1 row)

The containers and the network are gone, but not the volume.کانتینرها و شبکه حذف شدند، ولی volume نه.

✅ Brand-new containers, but coffee is still there: Compose reused the same volume.✅ کانتینرهای کاملاً جدید، ولی coffee هنوز هست: Compose از همان volume دوباره استفاده کرد.

Step 7قدم ۷

Remove everything, including the dataحذف همه‌چیز، حتی داده‌ها

Add -v to down to delete the project's volumes too:-v را به down اضافه کنید تا volumeهای پروژه هم حذف شوند:

bash
docker compose down -v
 …
 Volume compose-db_pgdata Removed      # the database is gone
 Network compose-db_default Removed
⚠

down -v deletes the project's databases for good. Use plain down for everyday stopping; use down -v only when you really want a fresh start.down -v دیتابیس‌های پروژه را برای همیشه حذف می‌کند. برای توقف روزمره از down ساده استفاده کنید؛ down -v را فقط وقتی بزنید که واقعاً یک شروع تازه می‌خواهید.

Summaryخلاصه

🎉 An app and its database, with Compose!🎉 یک برنامه و دیتابیسش، با Compose!

Several servicesچند سرویس

One compose.yaml; they reach each other by service nameیک compose.yaml؛ با نام سرویس به هم دسترسی دارند

env_file:

Like --env-fileمثل --env-file

volumes: (top level)(سطح بالا)

Declare the named volumes the services useاعلام named volumeهایی که سرویس‌ها استفاده می‌کنند

docker compose exec SERVICE …

Run a command in a service's containerاجرای دستور در کانتینر یک سرویس

docker compose down

Remove containers + network, keep volumesحذف کانتینرها + شبکه، volumeها می‌مانند

docker compose down -v

Also delete the volumes (data gone!)حذف volumeها هم (داده‌ها از بین می‌روند!)
