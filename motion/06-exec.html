Go inside a containerرفتن به داخل کانتینر

A container is like a small Linux machine. You'll open a shell inside the running nginx, look around, change its welcome page, and see your change in the browser.کانتینر مثل یک ماشین لینوکس کوچک است. یک شل داخل nginx در حال اجرا باز می‌کنید، اطراف را می‌گردید، صفحه‌ی خوش‌آمد آن را تغییر می‌دهید و تغییرتان را در مرورگر می‌بینید.

Step 2قدم ۲

Go insideرفتن به داخل

bash
docker exec -it web bash
root@118989b0b06f:/#
exec

Execute: run a command inside a container that is already running.Execute: یک دستور را داخل کانتینری اجرا می‌کند که از قبل در حال اجراست.

-it

Interactive + terminal: so you can type into it. Needed for a shell.Interactive + terminal: تا بتوانید در آن تایپ کنید. برای شل لازم است.

bash

The command to run: a shell.دستوری که اجرا می‌شود: یک شل.

🔑 Your prompt changed. You are now inside the container, as root. The name after @ is the container's ID.🔑 prompt شما عوض شد. حالا داخل کانتینر هستید، با کاربر root. نام بعد از @ شناسه‌ی کانتینر است.

Step 4قدم ۴

Change the pageتغییر صفحه

root@118989b0b06f · inside the containerداخل کانتینر
echo '<h1>Hello from my container!</h1>' > /usr/share/nginx/html/index.html
echo · >

echo prints the text, and > writes it into the file instead of the screen, replacing what was there.echo متن را چاپ می‌کند و > آن را به‌جای صفحه‌ی نمایش در فایل می‌نویسد و محتوای قبلی را جایگزین می‌کند.

💡 '…'

Note the single quotes '…'. With double quotes, the ! in the text confuses the shell and you get event not found. Single quotes pass the text exactly as written.به کوتیشن تکی '…' دقت کنید. با کوتیشن دوتایی، علامت ! در متن شل را گیج می‌کند و خطای event not found می‌گیرید. کوتیشن تکی متن را دقیقاً همان‌طور که نوشته شده می‌فرستد.

localhost:8080⟳

Hello from my container!

Now reload the browser tab: your page! 🎉حالا تب مرورگر را reload کنید: صفحه‌ی شما! 🎉

Step 4 · A questionقدم ۴ · یک سؤال

Why not open the file in nano?چرا فایل را با nano باز نکنیم؟

root@118989b0b06f · inside the containerداخل کانتینر
nano /usr/share/nginx/html/index.html
bash: nano: command not found
🔑

The nginx image has no nano and no vi. Images are kept small, so they only contain what the app needs.ایمیج nginx نه nano دارد نه vi. ایمیج‌ها کوچک نگه داشته می‌شوند و فقط چیزهایی را دارند که برنامه لازم دارد.

Step 5قدم ۵

Come back outبیرون آمدن

bash
exit
exit
$   ← your normal prompt is back
docker ps
CONTAINER ID   IMAGE     COMMAND                  CREATED         STATUS         PORTS                                     NAMES
118989b0b06f   nginx     "/docker-entrypoint.…"   3 minutes ago   Up 3 minutes   0.0.0.0:8080->80/tcp, [::]:8080->80/tcp   web
🔑

exit closed only the shell that exec started, not the container. The browser still shows your page. It's like Ctrl+C on docker logs -f in Lesson 5.exit فقط شلی را بست که exec باز کرده بود، نه کانتینر را. مرورگر هنوز صفحه‌ی شما را نشان می‌دهد. مثل Ctrl+C روی docker logs -f در درس ۵.

Step 6قدم ۶

Stop and start again: is my change still there?توقف و اجرای دوباره: تغییر من هنوز هست؟

bash
docker stop web
web
docker start web
web
localhost:8080

Hello from my container!

This site can't be reached

localhost refused to connect.

Hello from my container!

Reload the browser: nginx isn't running, so there is no page. But the container still exists, only stopped (remember docker ps -a from Lesson 3). Start the same container again:مرورگر را reload کنید: nginx اجرا نمی‌شود، پس صفحه‌ای نیست. ولی کانتینر هنوز وجود دارد، فقط متوقف شده (docker ps -a در درس ۳ یادتان هست؟). همان کانتینر را دوباره روشن کنید:

✅ Your change is still there. Stopping a container doesn't delete it, so its files are kept.✅ تغییر شما هنوز هست. متوقف کردن کانتینر آن را حذف نمی‌کند، پس فایل‌هایش باقی می‌مانند.

💡 docker start restarts an existing container, with the same name, port and files. docker run always creates a new one.💡 docker start یک کانتینر موجود را دوباره روشن می‌کند، با همان نام، پورت و فایل‌ها. docker run همیشه یک کانتینر جدید می‌سازد.

Step 7 · Why?قدم ۷ · چرا؟

You changed the container, not the imageشما کانتینر را تغییر دادید، نه ایمیج را

Deleting the container deleted the change. Every new container starts from the image, which never changed.با حذف کانتینر، تغییر هم حذف شد. هر کانتینر جدید از روی ایمیج ساخته می‌شود، و ایمیج هیچ‌وقت تغییر نکرد.

docker stop → docker start✅ kept: same containerباقی ماند: همان کانتینر
docker rm → docker run❌ lost: new container from the imageاز بین رفت: کانتینر جدید از روی ایمیج

Changes live only as long as the containerتغییرات فقط تا وقتی کانتینر هست باقی می‌مانند
