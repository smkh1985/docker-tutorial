The big pictureتصویر کلی

What you'll buildچیزی که می‌سازید

api: your own image, a small shop API written in Python with FastAPI.api: ایمیج خودتان، یک API فروشگاهی کوچک که با Python و FastAPI نوشته شده.

db: a PostgreSQL database. The API reaches it as db:5432, by service name.db: یک دیتابیس PostgreSQL. API با نام سرویس، به‌صورت db:5432 به آن می‌رسد.

The data lives in the named volume pgdata, so it survives.داده‌ها در named volume ای به نام pgdata هستند، پس باقی می‌مانند.

You talk to the API with curl or a browser on localhost:8000.شما با curl یا مرورگر روی localhost:8000 با API صحبت می‌کنید.

A table at startیک جدول در شروع

4 / 4

Two endpointsدو endpoint

GET /products lists products; POST /products?name=… adds one.GET /products محصولات را فهرست می‌کند؛ POST /products?name=… یکی اضافه می‌کند.

📄 main.py
import os import psycopgfrom fastapi import FastAPI app = FastAPI()DATABASE_URL = os.environ["DATABASE_URL"] with psycopg.connect(DATABASE_URL) as conn:    conn.execute("CREATE TABLE IF NOT EXISTS products (name text)")  @app.get("/products")def list_products():    with psycopg.connect(DATABASE_URL) as conn:        rows = conn.execute("SELECT name FROM products").fetchall()    return [row[0] for row in rows]  @app.post("/products")def add_product(name: str):    with psycopg.connect(DATABASE_URL) as conn:        conn.execute("INSERT INTO products (name) VALUES (%s)", (name,))    return {"added": name}
Step 3قدم ۳

The DockerfileDockerfile

The patterns from Lessons 19 and 20, with three things to notice:الگوهای درس‌های ۱۹ و ۲۰، با سه نکته‌ی قابل توجه:

📄 ~/shop-api/Dockerfile
FROM python:3.13-slimWORKDIR /appCOPY requirements.txt .RUN pip install -r requirements.txtCOPY . .EXPOSE 8000CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
1 / 3

requirements.txt is copied and installed before the rest of the project (COPY . .), so changing your code won't reinstall the libraries (caching, Lesson 19).requirements.txt قبل از بقیه‌ی پروژه (COPY . .) کپی و نصب می‌شود، تا تغییر کد باعث نصب دوباره‌ی کتابخانه‌ها نشود (cache، درس ۱۹).

2 / 3

--host 0.0.0.0 makes uvicorn listen on all network addresses of the container. By default it would only accept connections from inside the container, and -p couldn't reach it.--host 0.0.0.0 باعث می‌شود uvicorn روی همه‌ی آدرس‌های شبکه‌ی کانتینر گوش دهد. به‌طور پیش‌فرض فقط اتصال‌های داخل کانتینر را قبول می‌کند و -p نمی‌تواند به آن برسد.

3 / 3

COPY . . would also copy db.env, the password file (Lesson 20). Next slide: how to keep it out. 👉COPY . . فایل db.env، یعنی فایل رمز را هم کپی می‌کند (درس ۲۰). اسلاید بعد: چطور بیرون نگهش داریم. 👈

Step 3 · Keep secrets outقدم ۳ · رمزها را بیرون نگه دارید

Keep db.env out of the imagedb.env را بیرون از ایمیج نگه دارید

COPY . . copies everything in the folder… including db.env, the password file (Lesson 20). 😱COPY . . همه‌چیزِ پوشه را کپی می‌کند… حتی db.env، یعنی فایل رمز (درس ۲۰). 😱

Create .dockerignore to keep it, and the build files, out of the image:.dockerignore را بسازید تا آن و فایل‌های ساخت را بیرون از ایمیج نگه دارد:

📄 ~/shop-api/.dockerignore
db.envDockerfile.dockerignorecompose.yaml

✅ Now only your code goes into the image. The password stays on your PC.✅ حالا فقط کد شما وارد ایمیج می‌شود. رمز روی کامپیوتر شما می‌ماند.

Now one file describes both services. Press → to read it part by part.حالا یک فایل هر دو سرویس را توصیف می‌کند. → را بزنید تا بخش‌به‌بخش بخوانیمش.

Step 6قدم ۶

Why did the API restart?چرا API دوباره راه افتاد؟

Read the api service's logs. Like docker logs (Lesson 5), but by service name:لاگ‌های سرویس api را بخوانید. مثل docker logs (درس ۵)، ولی با نام سرویس:

bash · ~/shop-api
docker compose logs api
...
api-1  | psycopg.OperationalError: connection failed: connection to server at "172.26.0.2", port 5432 failed: Connection refused
...
api-1  | INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
db
⏳ PostgreSQL still starting…⏳ PostgreSQL هنوز در حال شروع…→✓ ready✓ آماده
api
start · connectشروع · اتصال→Connection refused 💥→↻ restart: unless-stopped→Uvicorn running ✅

Both containers started at almost the same time. The API tried to connect while PostgreSQL was still starting, got Connection refused, and crashed.هر دو کانتینر تقریباً هم‌زمان شروع شدند. API وقتی PostgreSQL هنوز در حال شروع بود سعی کرد وصل شود، Connection refused گرفت و crash کرد.

Then restart: unless-stopped (Lesson 12) started it again, and this time the database was ready: Uvicorn running. ✅بعد restart: unless-stopped (درس ۱۲) دوباره راهش انداخت و این بار دیتابیس آماده بود: Uvicorn running. ✅

🔑 This happens a lot in real projects: an app starts faster than its database. A restart policy is the simplest fix.🔑 این در پروژه‌های واقعی زیاد پیش می‌آید: برنامه سریع‌تر از دیتابیسش شروع می‌شود. سیاست راه‌اندازی مجدد ساده‌ترین راه‌حل است.
