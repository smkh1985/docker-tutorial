Step 1قدم ۱

Write a small programنوشتن یک برنامه‌ی کوچک

bash
mkdir ~/hello-app
cd ~/hello-app
nano app.py
app.py
import cowsay
cowsay.cow("Hello from my own image!")

It uses cowsay, a small Python library that draws a talking cow.از cowsay استفاده می‌کند، یک کتابخانه‌ی کوچک Python که یک گاو سخنگو می‌کشد.

🔑

cowsay is not part of Python, so it must be installed first. That's the job of the Dockerfile.cowsay جزو Python نیست، پس اول باید نصب شود. این کار Dockerfile است.

Step 2قدم ۲

Write the Dockerfileنوشتن Dockerfile

In the same folder, create Dockerfile with nano:در همان پوشه، با nano فایل Dockerfile را بسازید:

Dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY app.py .
RUN pip install cowsay
CMD ["python", "app.py"]
FROM python:3.13-slim

Start from the official Python image, a slim (smaller) version with Python 3.13 already installed.از ایمیج رسمی Python شروع کن، نسخه‌ی slim (کوچک‌تر) که Python 3.13 از قبل رویش نصب است.

WORKDIR /app

NEWجدیدCreate the folder /app in the image and work there from now on, like mkdir + cd.پوشه‌ی /app را در ایمیج بساز و از این به بعد همان‌جا کار کن، مثل mkdir + cd.

COPY app.py .

Copy your program in (Lesson 17). . means “here”, the WORKDIR: /app.برنامه‌تان را کپی کن (درس ۱۷). . یعنی «همین‌جا»، یعنی WORKDIR: /app.

RUN pip install cowsay

NEWجدیدRun a command while building. Here: install cowsay into the image.یک دستور را هنگام ساختن اجرا کن. اینجا: cowsay را داخل ایمیج نصب کن.

CMD ["python", "app.py"]

NEWجدیدThe command a container runs when it starts. You saw nginx's CMD in docker history (Lesson 16).دستوری که کانتینر هنگام شروع اجرا می‌کند. CMD مربوط به nginx را در docker history دیدید (درس ۱۶).

Step 2 · Two different timesقدم ۲ · دو زمان متفاوت

RUN or CMD: when?RUN یا CMD: کِی؟

🔑

RUN happens once, when you build the image. CMD happens every time a container starts.RUN یک بار، هنگام ساختن ایمیج اجرا می‌شود. CMD هر بار که یک کانتینر شروع می‌شود اجرا می‌شود.

Step 3قدم ۳

Build hello-appساختن hello-app

bash · ~/hello-app
docker build -t hello-app .
 => [1/4] FROM docker.io/library/python:3.13-slim@sha256:70729b46c69b4f1e
 => [2/4] WORKDIR /app
 => [3/4] COPY app.py .
 => [4/4] RUN pip install cowsay          # installing, at build time
 ...
 => => naming to docker.io/library/hello-app:latest

🐄 The container ran your CMD: python app.py.🐄 کانتینر CMD شما را اجرا کرد: python app.py.

🔑

Python and cowsay were already inside the image. No Python needed on your PC.Python و cowsay از قبل داخل ایمیج بودند. روی کامپیوتر شما Python لازم نیست.

Step 4قدم ۴

Change the program and rebuildتغییر برنامه و ساخت دوباره

app.py · nano
import cowsay
cowsay.cow("Hello from my own image!")cowsay.cow("Version 2 of my app!")

Open app.py with nano and change the text to "Version 2 of my app!". Then build again, the same way as in step 3:app.py را با nano باز کنید و متن را به "Version 2 of my app!" تغییر دهید. بعد دوباره، مثل قدم ۳، بسازید:

bash · ~/hello-app
docker build -t hello-app .
[+] Building 12.4s (9/9) FINISHED
 => [1/4] FROM docker.io/library/python:3.13-slim@sha256:70729b46c69b4f1e
 => CACHED [2/4] WORKDIR /app
 => [3/4] COPY app.py .                   # your code changed
 => [4/4] RUN pip install cowsay          # ← installing AGAIN?!
❓ You only changed one line of your code, so why did Docker install cowsay again?❓ شما فقط یک خط از کدتان را عوض کردید، پس چرا Docker دوباره cowsay را نصب کرد؟
Step 4 · Why?قدم ۴ · چرا؟

One line = one layerهر خط = یک لایه

[1/4]FROM python:3.13-slimCACHED ✓
[2/4]WORKDIR /appCACHED ✓
[3/4]COPY app.py .CHANGED ✎تغییر کرد ✎
[4/4]RUN pip install cowsayREBUILT ↻دوباره ساخته شد ↻

Each line makes a layerهر خط یک لایه می‌سازد

Each line of the Dockerfile makes one layer. Docker reuses (CACHED) a layer if nothing it depends on changed.هر خط Dockerfile یک لایه می‌سازد. Docker لایه‌ای را که هیچ چیزِ وابسته‌اش تغییر نکرده دوباره استفاده می‌کند (CACHED).

app.py changedapp.py عوض شد

app.py changed, so the COPY layer changed.app.py عوض شد، پس لایه‌ی COPY عوض شد.

…and everything after it…و همه‌ی لایه‌های بعد از آن

Once one layer changes, every layer after it is rebuilt. So the RUN layer after it was redone, even though cowsay didn't change at all.وقتی یک لایه تغییر کند، همه‌ی لایه‌های بعد از آن دوباره ساخته می‌شوند. پس لایه‌ی RUN بعد از آن دوباره انجام شد، با اینکه cowsay اصلاً تغییری نکرده بود.

Step 5قدم ۵

Fix the orderدرست کردن ترتیب

Open Dockerfile and move COPY app.py . to the line after RUN pip install cowsay:Dockerfile را باز کنید و COPY app.py . را به خط بعد از RUN pip install cowsay ببرید:

Dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY app.py .
RUN pip install cowsay
CMD ["python", "app.py"]

Build once to apply the new order. pip install runs one last time, because its position changed:یک بار بسازید تا ترتیب جدید اعمال شود. pip install یک بار دیگر اجرا می‌شود، چون جایش عوض شد:

bash · ~/hello-app
docker build -t hello-app .
🔑

Order matters. Put what changes rarely first (installing libraries), and what changes often last (your code).ترتیب مهم است. چیزی را که به‌ندرت عوض می‌شود اول بگذارید (نصب کتابخانه‌ها) و چیزی را که زیاد عوض می‌شود آخر (کد شما).

Step 5 · Try itقدم ۵ · امتحانش کنید

Now pip install is cachedحالا pip install در cache است

Now change app.py again, to "Version 3 of my app!", and build again:حالا دوباره app.py را تغییر دهید، به "Version 3 of my app!"، و دوباره بسازید:

bash · ~/hello-app
docker build -t hello-app .
[+] Building 5.6s (9/9) FINISHED
 => [1/4] FROM docker.io/library/python:3.13-slim@sha256:70729b46c69b4f1e
 => CACHED [2/4] WORKDIR /app
 => CACHED [3/4] RUN pip install cowsay   # ← reused!
 => [4/4] COPY app.py .                   # only your code
docker run --rm hello-app

  ====================
  ...

beforeقبل12.4s
nowحالا5.6s

✅ pip install is CACHED now: only your code was copied. With big projects, that's minutes saved on every build.✅ حالا pip install در وضعیت CACHED است: فقط کد شما کپی شد. در پروژه‌های بزرگ، این یعنی صرفه‌جویی چند دقیقه در هر ساخت.

Step 6قدم ۶

Clean upتمیزکاری

Thanks to --rm there are no containers to delete.به لطف --rm کانتینری برای حذف وجود ندارد.

bash
docker image rm hello-app

The command a container runs when it startsدستوری که کانتینر هنگام شروع اجرا می‌کند

Unchanged layers are reused: put rarely-changing steps firstلایه‌های بدون تغییر دوباره استفاده می‌شوند: مراحلی که کمتر عوض می‌شوند را اول بگذارید
