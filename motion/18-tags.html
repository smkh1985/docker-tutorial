LESSON 18 · name:tagدرس ۱۸ · name:tag

Real projects keep versions: if version 2 has a bug, you can go back to version 1.پروژه‌های واقعی نسخه‌ها را نگه می‌دارند: اگر نسخه‌ی ۲ باگ داشت، می‌توانید به نسخه‌ی ۱ برگردید.

🔑

You do that with tags, the part after the : in name:tag (Lesson 1).این کار را با تگ‌ها انجام می‌دهید، یعنی بخش بعد از : در name:tag (درس ۱).

Step 1قدم ۱

Build version 1ساختن نسخه‌ی ۱

bash
cd ~/my-site
echo '<h1>Version 1</h1>' > index.html
docker build -t my-site:v1 .
 ...
 => => naming to docker.io/library/my-site:v1

Build it, this time with a tag after the name:آن را بسازید، این بار با یک تگ بعد از نام:

my-sitenameنام:v1tagتگ

A tag can be anything:تگ می‌تواند هر چیزی باشد:

v11.02026-10-10…
Step 2قدم ۲

Build version 2ساختن نسخه‌ی ۲

bash · ~/my-site
echo '<h1>Version 2</h1>' > index.html
docker build -t my-site:v2 .
 ...
 => => naming to docker.io/library/my-site:v2
Step 3قدم ۳

List the versionsفهرست نسخه‌ها

bash
docker image ls my-site
IMAGE            ID             DISK USAGE   CONTENT SIZE   EXTRA
my-site:latest   14e42403a10d        240MB         63.9MB         # from Lesson 17
my-site:v1       eab935f421ad        240MB         63.9MB
my-site:v2       83073a48ca1d        240MB         63.9MB
🔑

Three images with the same name and different tags. Nothing was replaced: every version is kept.سه ایمیج با یک نام و تگ‌های مختلف. چیزی جایگزین نشد: همه‌ی نسخه‌ها نگه داشته شده‌اند.

Step 4قدم ۴

Run both side by sideاجرای هر دو کنار هم

bash
docker run -d --name web1 -p 8080:80 my-site:v1
docker run -d --name web2 -p 8081:80 my-site:v2
localhost:8080

Version 1

localhost:8081

Version 2

🔑 ROLLBACK

Two versions running at the same time. If version 2 had a bug, version 1 is right there: just run my-site:v1 again. That's a rollback.دو نسخه، هم‌زمان در حال اجرا. اگر نسخه‌ی ۲ باگ داشت، نسخه‌ی ۱ همین‌جاست: فقط my-site:v1 را دوباره اجرا کنید. به این کار rollback (برگشت به نسخه‌ی قبل) می‌گویند.

Step 5قدم ۵

latest is just a namelatest فقط یک نام است

Look at the list from step 3 again:دوباره به فهرست قدم ۳ نگاه کنید:

bash
IMAGE            ID             DISK USAGE   CONTENT SIZE   EXTRA
my-site:latest   14e42403a10d        240MB         63.9MB         # from Lesson 17
my-site:v1       eab935f421ad        240MB         63.9MB
my-site:v2       83073a48ca1d        240MB         63.9MB
≠

v2 is your newest build, but latest has a different ID: it's still the image from Lesson 17.v2 جدیدترین ساخت شماست، ولی latest شناسه‌ی متفاوتی دارد: هنوز همان ایمیج درس ۱۷ است.

🔑

latest does not mean “newest”. It's only the tag Docker uses when you don't give one. It doesn't move by itself.latest به معنی «جدیدترین» نیست. فقط تگی است که Docker وقتی تگ ندهید استفاده می‌کند. خودبه‌خود جابه‌جا نمی‌شود.

Step 5 · docker tagقدم ۵ · docker tag

Move latest yourselflatest را خودتان جابه‌جا کنید

docker tag gives an existing image another name:docker tag به یک ایمیج موجود یک نام دیگر می‌دهد:

bash
docker tag my-site:v2 my-site:latest
docker image ls my-site
IMAGE            ID             DISK USAGE   CONTENT SIZE   EXTRA
my-site:latest   83073a48ca1d        240MB         63.9MB
my-site:v1       eab935f421ad        240MB         63.9MB
my-site:v2       83073a48ca1d        240MB         63.9MB
=

Now latest and v2 have the same ID: one image with two names. No copy was made.حالا latest و v2 شناسه‌ی یکسان دارند: یک ایمیج با دو نام. هیچ کپی‌ای ساخته نشد.

The old latest lost its only name, so docker image ls no longer shows it. It still uses disk space; delete it by its ID from step 3 if you like: docker image rm 14e42403a10d, using your ID.latest قبلی تنها نامش را از دست داد، پس docker image ls دیگر آن را نشان نمی‌دهد. ولی هنوز فضای دیسک می‌گیرد؛ اگر خواستید با شناسه‌اش از قدم ۳ حذفش کنید: docker image rm 14e42403a10d، با شناسه‌ی خودتان.
