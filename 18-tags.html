Lesson 18 — Tags: keep versions درس ۱۸ — تگ‌ها: نگه داشتن نسخه‌ها

In Lesson 17, every rebuild of my-site replaced the previous one. Real projects keep versions: if version 2 has a bug, you can go back to version 1. You do that with tags, the part after the : in name:tag (Lesson 1).

در درس ۱۷، هر بار ساختن دوباره‌ی my-site نسخه‌ی قبلی را جایگزین کرد. پروژه‌های واقعی نسخه‌ها را نگه می‌دارند: اگر نسخه‌ی ۲ باگ داشت، می‌توانید به نسخه‌ی ۱ برگردید. این کار را با تگ‌ها انجام می‌دهید، یعنی بخش بعد از : در name:tag (درس ۱).

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Build version 1ساختن نسخه‌ی ۱ Doneانجام شد

Go to your my-site folder from Lesson 17, and replace the page's text with <h1>Version 1</h1>:

به پوشه‌ی my-site از درس ۱۷ بروید و متن صفحه را با <h1>Version 1</h1> جایگزین کنید:

bash
cd ~/my-site
echo '<h1>Version 1</h1>' > index.html

Build it, this time with a tag after the name:

آن را بسازید، این بار با یک تگ بعد از نام:

bash
docker build -t my-site:v1 .

my-site:v1 = name my-site, tag v1. A tag can be anything: v1, 1.0, 2026-10-10…

my-site:v1 یعنی نام my-site و تگ v1. تگ می‌تواند هر چیزی باشد: v1، 1.0، 2026-10-10 و …

2 Build version 2ساختن نسخه‌ی ۲ Doneانجام شد

Change the page to <h1>Version 2</h1>, and build it with the tag v2:

صفحه را به <h1>Version 2</h1> تغییر دهید و آن را با تگ v2 بسازید:

bash
echo '<h1>Version 2</h1>' > index.html
docker build -t my-site:v2 .

3 List the versionsفهرست نسخه‌ها Doneانجام شد

List only the my-site images:

فقط ایمیج‌های my-site را فهرست کنید:

bash
docker image ls my-site
output
IMAGE            ID             DISK USAGE   CONTENT SIZE   EXTRA
my-site:latest   14e42403a10d        240MB         63.9MB         # from Lesson 17
my-site:v1       eab935f421ad        240MB         63.9MB
my-site:v2       83073a48ca1d        240MB         63.9MB

Three images with the same name and different tags. Nothing was replaced: every version is kept.

سه ایمیج با یک نام و تگ‌های مختلف. چیزی جایگزین نشد: همه‌ی نسخه‌ها نگه داشته شده‌اند.

Checklistچک‌لیست

4 Run both versions side by sideاجرای هر دو نسخه کنار هم Doneانجام شد

Run version 1 named web1 on port 8080:

نسخه‌ی ۱ را با نام web1 روی پورت 8080 اجرا کنید:

bash
docker run -d --name web1 -p 8080:80 my-site:v1

Now run version 2 named web2. Port 8080 is taken (Lesson 4), so use 8081 on your PC:

حالا نسخه‌ی ۲ را با نام web2 اجرا کنید. پورت 8080 گرفته شده (درس ۴)، پس روی کامپیوترتان از 8081 استفاده کنید:

bash
docker run -d --name web2 -p 8081:80 my-site:v2

Open both tabs:

هر دو تب را باز کنید:

localhost:8080

Version 1

localhost:8081

Version 2

Two versions of your app, running at the same time. If version 2 had a bug, version 1 is right there: just run my-site:v1 again. That's a rollback.

دو نسخه از برنامه‌ی شما، هم‌زمان در حال اجرا. اگر نسخه‌ی ۲ باگ داشت، نسخه‌ی ۱ همین‌جاست: فقط my-site:v1 را دوباره اجرا کنید. به این کار rollback (برگشت به نسخه‌ی قبل) می‌گویند.

Checklistچک‌لیست

5 latest is just a namelatest فقط یک نام است Doneانجام شد

Look at the list from step 3 again. v2 is your newest build, but latest has a different ID: it's still the image from Lesson 17.

دوباره به فهرست قدم ۳ نگاه کنید. v2 جدیدترین ساخت شماست، ولی latest شناسه‌ی متفاوتی دارد: هنوز همان ایمیج درس ۱۷ است.

🔑 latest does not mean “newest”. It's only the tag Docker uses when you don't give one. It doesn't move by itself.

🔑 latest به معنی «جدیدترین» نیست. فقط تگی است که Docker وقتی تگ ندهید استفاده می‌کند. خودبه‌خود جابه‌جا نمی‌شود.

You can move it yourself. docker tag gives an existing image another name:

می‌توانید خودتان جابه‌جایش کنید. docker tag به یک ایمیج موجود یک نام دیگر می‌دهد:

bash
docker tag my-site:v2 my-site:latest
docker image ls my-site
output
IMAGE            ID             DISK USAGE   CONTENT SIZE   EXTRA
my-site:latest   83073a48ca1d        240MB         63.9MB
my-site:v1       eab935f421ad        240MB         63.9MB
my-site:v2       83073a48ca1d        240MB         63.9MB

Now latest and v2 have the same ID: one image with two names. No copy was made. (The old latest lost its only name, so docker image ls no longer shows it. It still uses disk space; delete it by its ID from step 3 if you like: docker image rm 14e42403a10d, using your ID.)

حالا latest و v2 شناسه‌ی یکسان دارند: یک ایمیج با دو نام. هیچ کپی‌ای ساخته نشد. (latest قبلی تنها نامش را از دست داد، پس docker image ls دیگر آن را نشان نمی‌دهد. ولی هنوز فضای دیسک می‌گیرد؛ اگر خواستید با شناسه‌اش از قدم ۳ حذفش کنید: docker image rm 14e42403a10d، با شناسه‌ی خودتان.)

6 Clean upتمیزکاری Doneانجام شد

Stop and delete web1 and web2 with one command:

web1 و web2 را با یک دستور متوقف و حذف کنید:

bash
docker rm -f web1 web2
