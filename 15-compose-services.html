Lesson 15 — Compose: an app and its database درس ۱۵ — Compose: یک برنامه و دیتابیسش

In Lesson 13 you connected Adminer to PostgreSQL with four commands: a network, two long docker runs… Now you'll write it all once in a compose.yaml, with the env file (Lesson 11) and a named volume (Lesson 9), and start it with one command.

در درس ۱۳ با چهار دستور Adminer را به PostgreSQL وصل کردید: یک شبکه، دو docker run طولانی… حالا همه را یک بار در یک compose.yaml می‌نویسید، با env file (درس ۱۱) و یک named volume (درس ۹)، و با یک دستور اجرا می‌کنید.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Project folder and env fileپوشه‌ی پروژه و env file Doneانجام شد

Make a project folder called compose-db in your home folder and go into it (Lesson 14):

یک پوشه‌ی پروژه به نام compose-db در پوشه‌ی خانه‌تان بسازید و واردش شوید (درس ۱۴):

bash
mkdir ~/compose-db
cd ~/compose-db

Create db.env with nano, with the same three settings as in Lesson 11:

با nano فایل db.env را با همان سه تنظیم درس ۱۱ بسازید:

db.env
POSTGRES_USER=ali
POSTGRES_PASSWORD=secret
POSTGRES_DB=shop

2 Write compose.yamlنوشتن compose.yaml Doneانجام شد

Create compose.yaml with nano in the same folder (mind the spaces):

با nano فایل compose.yaml را در همان پوشه بسازید (به فاصله‌ها دقت کنید):

compose.yaml
services:
  db:
    image: postgres:alpine
    env_file: db.env
    volumes:
      - pgdata:/var/lib/postgresql
  adminer:
    image: adminer
    ports:
      - "8080:8080"

volumes:
  pgdata:
compose.yaml Same asمعادل
db: / adminer:two services, like --name db and --name adminerدو سرویس، مثل --name db و --name adminer
env_file: db.env--env-file db.env (Lesson 11)(درس ۱۱)
- pgdata:/var/lib/postgresqla named volume on PostgreSQL's data folder, like -v (Lesson 9)یک named volume روی پوشه‌ی داده‌ی PostgreSQL، مثل -v (درس ۹)
- "8080:8080"-p 8080:8080 (only Adminer, for your browser)(فقط Adminer، برای مرورگر شما)
volumes: pgdata:At the bottom, without indentation: declare the named volume. Compose requires thisدر پایین، بدون تورفتگی: named volume را اعلام می‌کند. Compose این را لازم دارد
no network?شبکه نیست؟Compose creates one for the project and puts every service on it (Lesson 14)Compose یکی برای پروژه می‌سازد و همه‌ی سرویس‌ها را رویش می‌گذارد (درس ۱۴)

3 Start everythingاجرای همه‌چیز Doneانجام شد

Start the project in the background (Lesson 14):

پروژه را در پس‌زمینه اجرا کنید (درس ۱۴):

bash
docker compose up -d
output
[+] up 4/4
 ✔ Network compose-db_default     Created
 ✔ Volume compose-db_pgdata       Created
 ✔ Container compose-db-adminer-1 Started
 ✔ Container compose-db-db-1      Started

One command, four things: a network, a volume and two containers. List the project's containers:

یک دستور، چهار چیز: یک شبکه، یک volume و دو کانتینر. کانتینرهای پروژه را فهرست کنید:

bash
docker compose ps
output
NAME                   SERVICE   STATUS         PORTS
compose-db-adminer-1   adminer   Up 6 seconds   0.0.0.0:8080->8080/tcp, [::]:8080->8080/tcp
compose-db-db-1        db        Up 7 seconds   5432/tcp

db shows only 5432/tcp: PostgreSQL's port, not published to your PC (Lesson 13).

db فقط 5432/tcp را نشان می‌دهد: پورت PostgreSQL، که روی کامپیوتر شما منتشر نشده (درس ۱۳).

4 Log in by service nameورود با نام سرویس Doneانجام شد

Open http://localhost:8080 and log in. This time use the settings from db.env:

http://localhost:8080 را باز کنید و وارد شوید. این بار از تنظیمات db.env استفاده کنید:

SystemPostgreSQL
Serverdb ← the service name from compose.yaml← نام سرویس در compose.yaml
Usernameali
Passwordsecret
Databaseshop
localhost:8080

Schema: public

PostgreSQL » db » shop · Logged in as: ali

✅ Adminer found db by its service name, with no docker network create and no --network. The shop database is empty for now.

✅ Adminer، db را با نام سرویسش پیدا کرد، بدون docker network create و بدون --network. دیتابیس shop فعلاً خالی است.

5 Save some dataذخیره‌ی مقداری داده Doneانجام شد

Create a table products and add one product, using psql (Lesson 11) inside the db service:

با psql (درس ۱۱) داخل سرویس db، یک جدول products بسازید و یک محصول اضافه کنید:

bash
docker compose exec db psql -U ali -d shop -c "CREATE TABLE products (name text);" -c "INSERT INTO products VALUES ('coffee');"
output
CREATE TABLE
INSERT 0 1

docker compose exec is like docker exec, but you use the service name (db). Reload Adminer: the table products is there, with coffee in it.

docker compose exec مثل docker exec است، ولی از نام سرویس (db) استفاده می‌کنید. Adminer را reload کنید: جدول products آنجاست و coffee داخلش.

6 down, then up again: is the data still there?down و دوباره up: داده‌ها هنوز هستند؟ Doneانجام شد

Stop and delete the project's containers and network (Lesson 14):

کانتینرها و شبکه‌ی پروژه را متوقف و حذف کنید (درس ۱۴):

bash
docker compose down

The containers and the network are gone, but not the volume. Check the list of volumes:

کانتینرها و شبکه حذف شدند، ولی volume نه. فهرست volumeها را بررسی کنید:

bash
docker volume ls
output
DRIVER    VOLUME NAME
local     compose-db_pgdata

Start the project again, and ask for the products:

پروژه را دوباره اجرا کنید و محصولات را بپرسید:

bash
docker compose up -d
bash
docker compose exec db psql -U ali -d shop -c "SELECT * FROM products;"
output
  name
--------
 coffee
(1 row)

✅ Brand-new containers, but coffee is still there: Compose reused the same volume.

✅ کانتینرهای کاملاً جدید، ولی coffee هنوز هست: Compose از همان volume دوباره استفاده کرد.

Checklistچک‌لیست

7 Remove everything, including the dataحذف همه‌چیز، حتی داده‌ها Doneانجام شد

Add -v to down to delete the project's volumes too:

-v را به down اضافه کنید تا volumeهای پروژه هم حذف شوند:

bash
docker compose down -v
output
 …
 Volume compose-db_pgdata Removed      # the database is gone
 Network compose-db_default Removed

⚠ down -v deletes the project's databases for good. Use plain down for everyday stopping; use down -v only when you really want a fresh start.

⚠ down -v دیتابیس‌های پروژه را برای همیشه حذف می‌کند. برای توقف روزمره از down ساده استفاده کنید؛ down -v را فقط وقتی بزنید که واقعاً یک شروع تازه می‌خواهید.
