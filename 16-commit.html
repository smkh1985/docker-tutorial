Lesson 16 — Save a container as an image درس ۱۶ — ذخیره‌ی کانتینر به‌صورت ایمیج

In Lesson 6, your change to nginx's page was lost when you deleted the container. What if you could freeze the changed container into a new image, and start as many copies as you like? That's docker commit.

در درس ۶، تغییری که در صفحه‌ی nginx دادید با حذف کانتینر از بین رفت. چه می‌شد اگر می‌توانستید کانتینر تغییرکرده را به یک ایمیج جدید منجمد کنید و هر چند نسخه که خواستید از آن اجرا کنید؟ این کار docker commit است.

Changed containerکانتینر تغییرکردهweb
docker commit
New imageایمیج جدیدmy-web:handmade

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Start nginxاجرای nginx Doneانجام شد

Start nginx in the background, named web, reachable at localhost:8080:

nginx را در پس‌زمینه، با نام web و در دسترس روی localhost:8080 اجرا کنید:

bash
docker run -d --name web -p 8080:80 nginx

2 Copy your page in with docker cpکپی صفحه به داخل با docker cp Doneانجام شد

Make a folder commit-demo in your home folder and go into it:

یک پوشه به نام commit-demo در پوشه‌ی خانه‌تان بسازید و واردش شوید:

bash
mkdir ~/commit-demo
cd ~/commit-demo

Create index.html with the text <h1>Saved with commit!</h1> (remember the single quotes from Lesson 6):

index.html را با متن <h1>Saved with commit!</h1> بسازید (کوتیشن تکی درس ۶ یادتان باشد):

bash
echo '<h1>Saved with commit!</h1>' > index.html

Now copy the file from your PC into the container:

حالا فایل را از کامپیوترتان به داخل کانتینر کپی کنید:

bash
docker cp index.html web:/usr/share/nginx/html/index.html

docker cp FROM TO works like the normal cp. web: in front of a path means “inside the container web”. Reload the browser:

docker cp FROM TO مثل cp معمولی کار می‌کند. web: قبل از یک مسیر یعنی «داخل کانتینر web». مرورگر را reload کنید:

localhost:8080

Saved with commit!

❓ Can I copy out of a container too?❓ می‌توانم از کانتینر به بیرون هم کپی کنم؟

Yes, just swap the order: docker cp web:/etc/nginx/nginx.conf . copies nginx's config file to the current folder on your PC.

بله، فقط ترتیب را عوض کنید: docker cp web:/etc/nginx/nginx.conf . فایل تنظیمات nginx را به پوشه‌ی فعلی روی کامپیوتر شما کپی می‌کند.

3 Commit: save the container as an imagecommit: ذخیره‌ی کانتینر به‌صورت ایمیج Doneانجام شد

bash
docker commit web my-web:handmade
output
sha256:29c20f0b1052ab139b6aa90b8092cb60cf14d17d50ce2f74355a82d89c1a8fc4   # the new image's ID

docker commit CONTAINER NAME:TAG takes everything inside the container right now, including your page, and saves it as a new image. List it (Lesson 1):

docker commit CONTAINER NAME:TAG هر چیزی را که همین الان داخل کانتینر است، از جمله صفحه‌ی شما، به‌صورت یک ایمیج جدید ذخیره می‌کند. فهرستش کنید (درس ۱):

bash
docker image ls my-web
output
IMAGE             ID             DISK USAGE   CONTENT SIZE   EXTRA
my-web:handmade   29c20f0b1052        240MB         63.9MB

4 Run a new container from your imageاجرای کانتینر جدید از ایمیج شما Doneانجام شد

Delete web in one command:

web را با یک دستور حذف کنید:

bash
docker rm -f web

Start a new web like in step 1, but from my-web:handmade instead of nginx:

یک web جدید مثل قدم ۱ اجرا کنید، ولی به‌جای nginx از my-web:handmade:

bash
docker run -d --name web -p 8080:80 my-web:handmade
localhost:8080

Saved with commit!

✅ A brand-new container, and your page is there. In Lesson 6 it was lost; now it's saved in the image.

✅ یک کانتینر کاملاً جدید، و صفحه‌ی شما آنجاست. در درس ۶ از بین رفت؛ حالا در ایمیج ذخیره شده.

5 The catch: what's inside?مشکل کجاست: داخلش چیست؟ Doneانجام شد

An image is built in layers, one per step. docker history lists them, newest first:

یک ایمیج از لایه‌ها ساخته می‌شود، یکی برای هر مرحله. docker history آن‌ها را فهرست می‌کند، جدیدترین اول:

bash
docker history my-web:handmade
output
IMAGE          CREATED         CREATED BY                         SIZE
29c20f0b1052   5 seconds ago   nginx -g daemon off;               81.9kB    # ← your commit
f9ea18bfa4fa   4 days ago      CMD ["nginx" "-g" "daemon off;"]   0B        # ← nginx's own steps
<missing>      4 days ago      STOPSIGNAL SIGQUIT                 0B
<missing>      4 days ago      EXPOSE map[80/tcp:{}]              0B
...

nginx's layers show the exact steps its authors wrote (EXPOSE, CMD…). Your layer only says nginx -g daemon off;, which is just the program that was running. It says nothing about what you changed.

لایه‌های nginx دقیقاً مراحلی را که سازندگانش نوشته‌اند نشان می‌دهند (EXPOSE، CMD و …). لایه‌ی شما فقط می‌گوید nginx -g daemon off;، یعنی همان برنامه‌ای که در حال اجرا بود. هیچ چیزی درباره‌ی تغییری که دادید نمی‌گوید.

⚠ Problems with commit:

⚠ مشکلات commit:

  • Nobody can see what you changed or how, not even you a month later.هیچ‌کس نمی‌تواند ببیند چه چیزی را و چطور تغییر دادید، حتی خودتان یک ماه بعد.
  • To make version 2, you'd have to repeat every manual step by hand.برای ساختن نسخه‌ی ۲ باید همه‌ی مراحل دستی را دوباره با دست انجام دهید.
  • Anything else you did in the container (test files, mistakes) is saved too.هر کار دیگری که در کانتینر کردید (فایل‌های آزمایشی، اشتباه‌ها) هم ذخیره می‌شود.

🔑 commit is fine for a quick experiment. For real images, the steps should be written down, so anyone can read them and build the same image again. That's what a Dockerfile is: the next lesson.

🔑 commit برای یک آزمایش سریع خوب است. برای ایمیج‌های واقعی، مراحل باید نوشته شوند تا هر کسی بتواند آن‌ها را بخواند و همان ایمیج را دوباره بسازد. Dockerfile همین است: موضوع درس بعد.
