Lesson 21 — System packages and a safer image درس ۲۱ — بسته‌های سیستمی و یک ایمیج امن‌تر

In Lesson 19 you installed a Python library with pip. Programs often also need system tools, installed with Linux's package manager apt-get. You'll install one the right way, then make your image safer by not running as root.

در درس ۱۹ یک کتابخانه‌ی Python را با pip نصب کردید. برنامه‌ها اغلب به ابزارهای سیستمی هم نیاز دارند که با مدیر بسته‌ی لینوکس، apt-get، نصب می‌شوند. یکی را به روش درست نصب می‌کنید، بعد ایمیج‌تان را با اجرا نکردن به‌عنوان root امن‌تر می‌کنید.

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 A missing toolیک ابزار ناموجود Doneانجام شد

figlet is a small Linux tool that prints text as big letters. Try it in a new python:3.13-slim container (Lesson 7):

figlet یک ابزار کوچک لینوکس است که متن را با حروف بزرگ چاپ می‌کند. آن را در یک کانتینر جدید python:3.13-slim امتحان کنید (درس ۷):

bash
docker run --rm python:3.13-slim figlet Hi
output
docker: Error response from daemon: … exec: "figlet": executable file not found in $PATH

❌ Not there. Slim images contain only the basics, so you install what your app needs.

❌ نیست. ایمیج‌های slim فقط چیزهای پایه را دارند، پس هر چه برنامه‌تان لازم دارد را خودتان نصب می‌کنید.

2 Install it with apt-getنصب با apt-get Doneانجام شد

Make a folder fig-app in your home folder and go into it:

یک پوشه به نام fig-app در پوشه‌ی خانه‌تان بسازید و واردش شوید:

bash
mkdir ~/fig-app
cd ~/fig-app

Create Dockerfile with nano:

با nano فایل Dockerfile را بسازید:

Dockerfile
FROM python:3.13-slim
RUN apt-get update && apt-get install -y figlet && rm -rf /var/lib/apt/lists/*
CMD ["figlet", "Hello!"]

The RUN line is three commands joined by && (“and then, if it worked”):

خط RUN سه دستور است که با && («و بعد، اگر موفق بود») به هم وصل شده‌اند:

apt-get updateDownload the list of available packages (Lesson 0 did the same on your PC)فهرست بسته‌های موجود را دانلود کن (درس ۰ همین کار را روی کامپیوتر شما کرد)
apt-get install -y figletInstall figlet. -y answers “yes”, because nobody can type during a buildfiglet را نصب کن. -y جواب «بله» می‌دهد، چون هنگام build کسی نمی‌تواند تایپ کند
rm -rf /var/lib/apt/lists/*Delete that downloaded list: it's not needed anymore and only makes the image biggerآن فهرست دانلودشده را پاک کن: دیگر لازم نیست و فقط ایمیج را بزرگ‌تر می‌کند

Build the image fig-app and run it, deleting the container afterwards:

ایمیج fig-app را بسازید و اجرایش کنید و بعد کانتینر را حذف کنید:

bash
docker build -t fig-app .
docker run --rm fig-app
output
 _   _      _ _       _
| | | | ___| | | ___ | |
| |_| |/ _ \ | |/ _ \| |
|  _  |  __/ | | (_) |_|
|_| |_|\___|_|_|\___/(_)

3 Why one RUN with &&?چرا یک RUN با &&؟ Doneانجام شد

Each RUN makes a layer (Lesson 19), and a layer is never made smaller by a later one. If you write the steps as separate RUN lines, the downloaded package list stays saved in its own layer, even if a later line deletes it. We built both versions and compared:

هر RUN یک لایه می‌سازد (درس ۱۹) و هیچ لایه‌ای با لایه‌های بعدی کوچک‌تر نمی‌شود. اگر مراحل را در خط‌های RUN جدا بنویسید، فهرست بسته‌های دانلودشده در لایه‌ی خودش ذخیره می‌ماند، حتی اگر خط بعدی آن را پاک کند. هر دو نسخه را ساختیم و مقایسه کردیم:

DockerfileImage sizeاندازه‌ی ایمیج
RUN apt-get update
RUN apt-get install -y figlet		216 MB
RUN apt-get update && apt-get install -y figlet && rm -rf /var/lib/apt/lists/*178 MB ✅

🔑 Install system packages in one RUN: update && install -y && clean up. You'll see this pattern in almost every real Dockerfile.

🔑 بسته‌های سیستمی را در یک RUN نصب کنید: update && install -y && پاک‌سازی. این الگو را تقریباً در هر Dockerfile واقعی می‌بینید.

4 Who am I inside the container?داخل کانتینر من کی هستم؟ Doneانجام شد

Run whoami in a new fig-app container:

whoami را در یک کانتینر جدید fig-app اجرا کنید:

bash
docker run --rm fig-app whoami
output
root

Your program runs as root, the all-powerful user (you saw root@… in Lesson 6). If someone finds a bug in your app and breaks in, they're root inside the container, which makes it much easier to do damage.

برنامه‌ی شما به‌عنوان root، کاربر همه‌کاره، اجرا می‌شود (در درس ۶ root@… را دیدید). اگر کسی باگی در برنامه‌تان پیدا کند و وارد شود، داخل کانتینر root است، که آسیب زدن را خیلی راحت‌تر می‌کند.

Checklistچک‌لیست

5 Run as a normal user with USERاجرا با کاربر معمولی با USER Doneانجام شد

Add two lines before CMD: create a normal user called app, then switch to it:

دو خط قبل از CMD اضافه کنید: یک کاربر معمولی به نام app بسازید، بعد به آن سوئیچ کنید:

Dockerfile
FROM python:3.13-slim
RUN apt-get update && apt-get install -y figlet && rm -rf /var/lib/apt/lists/*
RUN useradd --create-home app
USER app
CMD ["figlet", "Hello!"]
RUN useradd --create-home appCreate a Linux user named app, with a home folderیک کاربر لینوکس به نام app با پوشه‌ی خانه بساز
USER appNew: from here on, and when the container runs, be app instead of rootجدید: از اینجا به بعد، و هنگام اجرای کانتینر، به‌جای root، کاربر app باش

USER comes after apt-get: installing needs root, running doesn't. Rebuild, and ask again (step 4):

USER بعد از apt-get می‌آید: نصب کردن root لازم دارد، اجرا کردن نه. دوباره بسازید و دوباره بپرسید (قدم ۴):

bash
docker build -t fig-app .
docker run --rm fig-app whoami
output
app

✅ Now it runs as app, and docker run --rm fig-app still prints the banner. A normal user can't install software or change the system. Try it:

✅ حالا به‌عنوان app اجرا می‌شود و docker run --rm fig-app هنوز بنر را چاپ می‌کند. یک کاربر معمولی نمی‌تواند نرم‌افزار نصب کند یا سیستم را تغییر دهد. امتحان کنید:

bash
docker run --rm fig-app apt-get install -y curl
output
E: Could not open lock file /var/lib/dpkg/lock-frontend - open (13: Permission denied)
E: Unable to acquire the dpkg frontend lock (/var/lib/dpkg/lock-frontend), are you root?

🔑 Install as root, then switch with USER before CMD. Your app does its job, and an attacker gets much less power.

🔑 با root نصب کنید، بعد قبل از CMD با USER سوئیچ کنید. برنامه‌ی شما کارش را انجام می‌دهد و یک مهاجم قدرت خیلی کمتری می‌گیرد.
