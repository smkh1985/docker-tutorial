System packages and a safer imageبسته‌های سیستمی و یک ایمیج امن‌تر

In Lesson 19 you installed a Python library with pip. Programs often also need system tools, installed with Linux's package manager apt-get. You'll install one the right way, then make your image safer by not running as root.در درس ۱۹ یک کتابخانه‌ی Python را با pip نصب کردید. برنامه‌ها اغلب به ابزارهای سیستمی هم نیاز دارند که با مدیر بسته‌ی لینوکس، apt-get، نصب می‌شوند. یکی را به روش درست نصب می‌کنید، بعد ایمیج‌تان را با اجرا نکردن به‌عنوان root امن‌تر می‌کنید.

Press → or Space to startبرای شروع → یا Space را بزنید

Step 1قدم ۱

A missing toolیک ابزار ناموجود

figlet is a small Linux tool that prints text as big letters. Try it in a new python:3.13-slim container (Lesson 7):figlet یک ابزار کوچک لینوکس است که متن را با حروف بزرگ چاپ می‌کند. آن را در یک کانتینر جدید python:3.13-slim امتحان کنید (درس ۷):

bash
docker run --rm python:3.13-slim figlet Hi
docker: Error response from daemon: … exec: "figlet": executable file not found in $PATH
NOT THEREنیست

❌ Not there. Slim images contain only the basics, so you install what your app needs.❌ نیست. ایمیج‌های slim فقط چیزهای پایه را دارند، پس هر چه برنامه‌تان لازم دارد را خودتان نصب می‌کنید.

Step 2قدم ۲

Install it with apt-getنصب با apt-get

Make a folder fig-app in your home folder and go into it:یک پوشه به نام fig-app در پوشه‌ی خانه‌تان بسازید و واردش شوید:

bash
mkdir ~/fig-app
cd ~/fig-app

Create Dockerfile with nano:با nano فایل Dockerfile را بسازید:

📄 ~/fig-app/Dockerfile
FROM python:3.13-slimRUN apt-get update && apt-get install -y figlet && rm -rf /var/lib/apt/lists/*CMD ["figlet", "Hello!"]

👆 The RUN line installs figlet. Let's read it piece by piece.👆 خط RUN، figlet را نصب می‌کند. بیایید تکه‌تکه بخوانیمش.

Step 2 · The RUN lineقدم ۲ · خط RUN

Three commands joined by &&سه دستور که با && وصل شده‌اند

RUN apt-get update&& apt-get install -y figlet&& rm -rf /var/lib/apt/lists/*

The RUN line is three commands joined by && (“and then, if it worked”).خط RUN سه دستور است که با && («و بعد، اگر موفق بود») به هم وصل شده‌اند.

apt-get update

Download the list of available packages (Lesson 0 did the same on your PC).فهرست بسته‌های موجود را دانلود کن (درس ۰ همین کار را روی کامپیوتر شما کرد).

apt-get install -y figlet

Install figlet. -y answers “yes”, because nobody can type during a build.figlet را نصب کن. -y جواب «بله» می‌دهد، چون هنگام build کسی نمی‌تواند تایپ کند.

rm -rf /var/lib/apt/lists/*

Delete that downloaded list: it's not needed anymore and only makes the image bigger.آن فهرست دانلودشده را پاک کن: دیگر لازم نیست و فقط ایمیج را بزرگ‌تر می‌کند.

Step 2 · Try itقدم ۲ · امتحان کنید

Build and runبسازید و اجرا کنید

Build the image fig-app and run it, deleting the container afterwards:ایمیج fig-app را بسازید و اجرایش کنید و بعد کانتینر را حذف کنید:

bash · ~/fig-app
docker build -t fig-app .
docker run --rm fig-app

You see “Hello!” in big letters: figlet is installed in your image.«Hello!» را با حروف بزرگ می‌بینید: figlet در ایمیج شما نصب شده است.

Step 3قدم ۳

Why one RUN with &&?چرا یک RUN با &&؟

Each RUN makes a layer (Lesson 19), and a layer is never made smaller by a later one. With separate RUN lines, the downloaded package list stays saved in its own layer, even if a later line deletes it. We built both versions and compared:هر RUN یک لایه می‌سازد (درس ۱۹) و هیچ لایه‌ای با لایه‌های بعدی کوچک‌تر نمی‌شود. اگر مراحل را در خط‌های RUN جدا بنویسید، فهرست بسته‌های دانلودشده در لایه‌ی خودش ذخیره می‌ماند، حتی اگر خط بعدی آن را پاک کند. هر دو نسخه را ساختیم و مقایسه کردیم:

SEPARATE RUN LINESخط‌های RUN جدا
RUN apt-get update
RUN apt-get install -y figlet
0 MB
ONE RUNیک RUN
RUN apt-get update && apt-get install -y figlet && rm -rf /var/lib/apt/lists/*
0 MB ✅
🔑

Install system packages in one RUN: update && install -y && clean up. You'll see this pattern in almost every real Dockerfile.بسته‌های سیستمی را در یک RUN نصب کنید: update && install -y && پاک‌سازی. این الگو را تقریباً در هر Dockerfile واقعی می‌بینید.

Step 4قدم ۴

Who am I inside the container?داخل کانتینر من کی هستم؟

bash
docker run --rm fig-app whoami
root

Your program runs as root, the all-powerful user (you saw root@… in Lesson 6).برنامه‌ی شما به‌عنوان root، کاربر همه‌کاره، اجرا می‌شود (در درس ۶ root@… را دیدید).

If someone finds a bug in your app and breaks in, they're root inside the container, which makes it much easier to do damage.اگر کسی باگی در برنامه‌تان پیدا کند و وارد شود، داخل کانتینر root است، که آسیب زدن را خیلی راحت‌تر می‌کند.

Step 5قدم ۵

Run as a normal user with USERاجرا با کاربر معمولی با USER

Add two lines before CMD: create a normal user called app, then switch to it:دو خط قبل از CMD اضافه کنید: یک کاربر معمولی به نام app بسازید، بعد به آن سوئیچ کنید:

📄 ~/fig-app/Dockerfile
FROM python:3.13-slimRUN apt-get update && apt-get install -y figlet && rm -rf /var/lib/apt/lists/*RUN useradd --create-home appUSER appCMD ["figlet", "Hello!"]
👑 root · installs👑 root · نصب 🙂 app · runs🙂 app · اجرا

RUN useradd --create-home app

Create a Linux user named app, with a home folder.یک کاربر لینوکس به نام app با پوشه‌ی خانه بساز.

USER app · new· جدید

From here on, and when the container runs, be app instead of root.از اینجا به بعد، و هنگام اجرای کانتینر، به‌جای root، کاربر app باش.

Order mattersترتیب مهم است

USER comes after apt-get: installing needs root, running doesn't.USER بعد از apt-get می‌آید: نصب کردن root لازم دارد، اجرا کردن نه.

Rebuild and ask againدوباره بسازید و دوباره بپرسید

bash · ~/fig-app
docker build -t fig-app .
docker run --rm fig-app whoami
app

✅ Now it runs as app, and docker run --rm fig-app still prints the banner. A normal user can't install software or change the system. Try it 👈✅ حالا به‌عنوان app اجرا می‌شود و docker run --rm fig-app هنوز بنر را چاپ می‌کند. یک کاربر معمولی نمی‌تواند نرم‌افزار نصب کند یا سیستم را تغییر دهد. امتحان کنید 👉

🔑

Install as root, then switch with USER before CMD. Your app does its job, and an attacker gets much less power.با root نصب کنید، بعد قبل از CMD با USER سوئیچ کنید. برنامه‌ی شما کارش را انجام می‌دهد و یک مهاجم قدرت خیلی کمتری می‌گیرد.
