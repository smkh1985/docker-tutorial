Lesson 9 — Named volumes, with a real database درس ۹ — Named volume، با یک دیتابیس واقعی

In Lesson 8 you gave -v a folder on your PC. There is a second way: give it just a name, and Docker creates and manages the storage for you. This is what you normally use for databases, so this time you'll use a real one: Redis.

در درس ۸ به -v یک پوشه روی کامپیوترتان دادید. راه دومی هم هست: فقط یک نام بدهید، و Docker خودش محل ذخیره‌سازی را می‌سازد و مدیریت می‌کند. برای دیتابیس‌ها معمولاً از همین استفاده می‌شود، پس این بار از یک دیتابیس واقعی استفاده می‌کنید: Redis.

-v ~/my-data:/datastarts with a path → a folder on your PC (bind mount, Lesson 8)با یک مسیر شروع می‌شود ← یک پوشه روی کامپیوتر شما (bind mount، درس ۸)
-v redisdata:/datajust a name → storage managed by Docker (named volume, this lesson)فقط یک نام ← محل ذخیره‌ای که Docker مدیریت می‌کند (named volume، این درس)

🧠 Blurred commands are ones you've already learned. Try to remember them, then click to check.

🧠 دستورهای محو را قبلاً یاد گرفته‌اید. سعی کنید به یاد بیاورید، بعد کلیک کنید و ببینید.

1 Start Redisاجرای Redis Doneانجام شد

Redis is a small, very fast, very popular database. Start it in the background and name it cache:

Redis یک دیتابیس کوچک، خیلی سریع و خیلی محبوب است. آن را در پس‌زمینه اجرا کنید و نامش را cache بگذارید:

bash
docker run -d --name cache redis:alpine
output
Unable to find image 'redis:alpine' locally
...
Status: Downloaded newer image for redis:alpine
35c75bbc9363446f7ffa3b7a710f438cdc525f91e7730d3353d35eead8eaf400

The tag alpine means a small version of the image, built on Alpine Linux (Lesson 1).

تگ alpine یعنی نسخه‌ی کوچک ایمیج که روی Alpine Linux ساخته شده (درس ۱).

2 Count visitsشمردن بازدیدها Doneانجام شد

Imagine every page visit on your website adds 1 to a counter in the database. Run this three times:

فرض کنید هر بازدید از وب‌سایت شما یک واحد به یک شمارنده در دیتابیس اضافه می‌کند. این را سه بار اجرا کنید:

bash
docker exec cache redis-cli INCR visits
output
1
2
3

Redis's command-line tool. It's inside the image.ابزار خط فرمان Redis. داخل ایمیج هست.

3 Recreate the container: does the counter remember?ساخت دوباره‌ی کانتینر: شمارنده یادش می‌ماند؟ Doneانجام شد

Stop cache cleanly, then delete it (two commands, Lesson 3):

cache را با آرامش متوقف کنید و بعد حذفش کنید (دو دستور، درس ۳):

bash

یک کانتینر جدید دقیقاً مثل قدم ۱ اجرا کنید و یک بار دیگر بشمارید:

bash

1

❌ دوباره 1. دیتابیس همه‌ی بازدیدها را فراموش کرد. کانتینرها موقتی هستند (درس ۸).

4 Add a named volumeاضافه کردن named volume Doneانجام شد

To keep the data, we must put a volume on the folder where Redis saves it. Which folder is that? Ask Redis (the cache container from step 3 is still running):

برای نگه داشتن داده‌ها باید volume را روی پوشه‌ای بگذاریم که Redis داده‌ها را آنجا ذخیره می‌کند. کدام پوشه؟ از خود Redis بپرسید (کانتینر cache از قدم ۳ هنوز در حال اجراست):

bash
docker exec cache redis-cli CONFIG GET dir
output
dir
/data

Redis saves its data in /data, in a file called dump.rdb. The official Redis image sets this up, and its page on Docker Hub says so. That's the folder our volume must cover.

Redis داده‌هایش را در /data ذخیره می‌کند، در فایلی به نام dump.rdb. ایمیج رسمی Redis این را تنظیم کرده و صفحه‌اش در Docker Hub هم همین را می‌گوید. این همان پوشه‌ای است که volume ما باید رویش قرار بگیرد.

💡 Every database keeps its data in its own folder, e.g. PostgreSQL keeps its data under /var/lib/postgresql. Before adding a volume, check the image's page on Docker Hub. A volume on the wrong folder saves nothing.

💡 هر دیتابیس داده‌هایش را در پوشه‌ی خودش نگه می‌دارد، مثلاً PostgreSQL داده‌هایش را زیر /var/lib/postgresql نگه می‌دارد. قبل از اضافه کردن volume، صفحه‌ی ایمیج را در Docker Hub ببینید. volume روی پوشه‌ی اشتباه هیچ چیزی را نگه نمی‌دارد.

Now stop and delete cache, cleanly:

حالا cache را با آرامش متوقف و حذف کنید:

bash
docker stop cache
docker rm cache

This time, put a named volume on /data:

این بار یک named volume روی /data بگذارید:

bash
docker run -d --name cache -v redisdata:/data redis:alpine

Before the : there's a name (redisdata), not a path. No mkdir needed: if the volume doesn't exist yet, Docker creates it.

قبل از : یک نام (redisdata) آمده، نه مسیر. mkdir لازم نیست: اگر volume هنوز وجود نداشته باشد، Docker آن را می‌سازد.

💡 /data already exists in the image. The volume does not go inside it (there is no /data/data): it takes the place of /data. Whatever Redis writes to /data lands in the volume.

💡 پوشه‌ی /data از قبل در ایمیج وجود دارد. volume داخل آن نمی‌رود (چیزی به نام /data/data نداریم): بلکه جای /data را می‌گیرد. هر چه Redis در /data بنویسد، در volume ذخیره می‌شود.

Count three times again:

دوباره سه بار بشمارید:

bash
docker exec cache redis-cli INCR visits
output
1
2
3

5 See your volumeدیدن volume Doneانجام شد

Named volumes have their own list, like images and containers:

named volumeها هم مثل ایمیج‌ها و کانتینرها فهرست خودشان را دارند:

bash
docker volume ls
output
DRIVER    VOLUME NAME
local     redisdata

You may see other volumes too, created by other projects on your PC.

ممکن است volumeهای دیگری هم ببینید که پروژه‌های دیگر روی کامپیوتر شما ساخته‌اند.

Where is it actually stored? Ask Docker:

واقعاً کجا ذخیره شده؟ از Docker بپرسید:

bash
docker volume inspect redisdata
output
[
    {
        "Driver": "local",
        "Mountpoint": "/var/lib/docker/volumes/redisdata/_data",   # the default; can differ
        "Name": "redisdata",
        ...
    }
]

It's in Docker's own storage folder, owned by root. You don't open it yourself: you use it through containers, and Docker takes care of it.

در پوشه‌ی ذخیره‌سازی خود Docker است که مال root است. خودتان بازش نمی‌کنید: از طریق کانتینرها از آن استفاده می‌کنید و Docker مراقبش است.

The _data folder on your PC is /data inside the container: two names for the same folder.

پوشه‌ی _data روی کامپیوتر شما همان /data داخل کانتینر است: دو نام برای یک پوشه.

❓ Is my ~/my-data folder from Lesson 8 in this list?❓ پوشه‌ی ~/my-data از درس ۸ در این فهرست هست؟

No. docker volume ls lists only volumes that Docker manages. A bind mount is just a folder on your PC, so it never appears there. To see what a container has mounted (of either kind), inspect the container and look for "Mounts" in its (long) output:

نه. docker volume ls فقط volumeهایی را فهرست می‌کند که Docker مدیریت می‌کند. bind mount فقط یک پوشه روی کامپیوتر شماست، پس هیچ‌وقت آنجا نمی‌آید. برای دیدن چیزهایی که یک کانتینر mount کرده (از هر دو نوع)، خود کانتینر را inspect کنید و در خروجی (طولانی) آن دنبال "Mounts" بگردید:

bash
docker inspect cache
output
        "Mounts": [
            {
                "Type": "volume",          # a named volume
                "Name": "redisdata",
                "Destination": "/data",
                ...
            }
        ],

For a bind mount, like Lesson 8's app, it shows "Type": "bind" and your PC folder as "Source".

برای یک bind mount، مثل app در درس ۸، "Type": "bind" و پوشه‌ی کامپیوتر شما را به‌عنوان "Source" نشان می‌دهد.

6 Recreate again: does it remember now?ساخت دوباره: حالا یادش می‌ماند؟ Doneانجام شد

Stop and delete cache cleanly:

cache را با آرامش متوقف و حذف کنید:

bash
docker stop cache
docker rm cache

Start a new one exactly like in step 4 (same volume), and count once:

یک کانتینر جدید دقیقاً مثل قدم ۴ (با همان volume) اجرا کنید و یک بار بشمارید:

bash
docker run -d --name cache -v redisdata:/data redis:alpine
docker exec cache redis-cli INCR visits
output
4

✅ 4! The new container continued where the old one stopped. When you ran docker stop, Redis saved its data to /data, which is the volume, and the volume outlived the container.

✅ 4! کانتینر جدید از همان جایی ادامه داد که قبلی متوقف شده بود. وقتی docker stop زدید، Redis داده‌هایش را در /data ذخیره کرد، که همان volume است، و volume بیشتر از کانتینر عمر کرد.

See the saved file inside the volume:

فایل ذخیره‌شده را داخل volume ببینید:

bash
docker exec cache ls -l /data
output
-rw-------    1 redis    redis          104 Oct 10 10:48 dump.rdb

That's the database file Redis wrote when you stopped the old container.

این همان فایل دیتابیس است که Redis هنگام متوقف کردن کانتینر قبلی نوشت.

After recreating, INCR prints…بعد از ساخت دوباره، INCR چاپ می‌کند…
without a volume (step 3)بدون volume (قدم ۳)❌ 1
with -v redisdata:/data (step 6)با -v redisdata:/data (قدم ۶)✅ 4

⚠ Stop databases cleanly. Redis keeps data in memory and saves it to disk when it stops. docker rm -f kills it before it can save. We tried it: we counted to 5, ran rm -f, and the new container had 3, the value from the last clean stop. The last visits were lost, even with a volume. Why? A volume only keeps what Redis has written to disk (dumped to dump.rdb). Changes that are still only in memory, not dumped yet, are lost. You can see it yourself: before the first docker stop, /data is still empty. Redis also saves by itself from time to time, but you can't count on the latest changes being saved. Use docker stop first.

⚠ دیتابیس‌ها را با آرامش متوقف کنید. Redis داده‌ها را در حافظه نگه می‌دارد و وقتی متوقف می‌شود روی دیسک ذخیره‌شان می‌کند. docker rm -f آن را قبل از ذخیره کردن از کار می‌اندازد. امتحانش کردیم: تا 5 شمردیم، rm -f زدیم، و کانتینر جدید 3 داشت، یعنی مقدار آخرین توقف آرام. آخرین بازدیدها از دست رفتند، حتی با volume. چرا؟ volume فقط چیزی را نگه می‌دارد که Redis روی دیسک نوشته باشد (در dump.rdb ذخیره کرده باشد). تغییراتی که هنوز فقط در حافظه هستند و ذخیره نشده‌اند، از دست می‌روند. خودتان می‌توانید ببینید: قبل از اولین docker stop، پوشه‌ی /data هنوز خالی است. Redis هر از گاهی خودش هم ذخیره می‌کند، اما نمی‌شود روی ذخیره شدن آخرین تغییرات حساب کرد. اول از docker stop استفاده کنید.

7 Delete the volumeحذف volume Doneانجام شد

Try to delete the volume:

سعی کنید volume را حذف کنید:

bash
docker volume rm redisdata
output
Error response from daemon: remove redisdata: volume is in use - [73dbe5f93b9c…]

Docker refuses: cache is still using it. This protects you from deleting a database under a running app. Stop and delete the container first:

Docker قبول نمی‌کند: cache هنوز از آن استفاده می‌کند. این از شما محافظت می‌کند تا دیتابیس را از زیر پای یک برنامه‌ی در حال اجرا پاک نکنید. اول کانتینر را متوقف و حذف کنید:

bash
docker stop cache
docker rm cache

Now delete the volume, and check the list:

حالا volume را حذف کنید و فهرست را بررسی کنید:

bash
docker volume rm redisdata
docker volume ls

⚠ docker volume rm deletes the data for good. There is no undo. Double-check the name, especially on a machine with real databases.

⚠ docker volume rm داده‌ها را برای همیشه حذف می‌کند. راه برگشتی نیست. نام را دوباره بررسی کنید، مخصوصاً روی سیستمی که دیتابیس‌های واقعی دارد.
