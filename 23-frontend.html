2 The frontend codeکد frontend Doneانجام شد

Create frontend/requirements.txt:

frontend/requirements.txt را بسازید:

frontend/requirements.txt
streamlit
requests

streamlit makes the web page; requests calls your API. Now frontend/app.py:

streamlit صفحه‌ی وب را می‌سازد؛ requests API شما را صدا می‌زند. حالا frontend/app.py:

frontend/app.py
import os

import requests
import streamlit as st

API_URL = os.environ["API_URL"]

st.title("My shop")

name = st.text_input("New product")
if st.button("Add") and name:
    requests.post(f"{API_URL}/products", params={"name": name})

st.subheader("Products")
for product in requests.get(f"{API_URL}/products").json():
    st.write("•", product)
  • It reads the API's address from the environment variable API_URL (Lesson 11).آدرس API را از متغیر محیطی API_URL می‌خواند (درس ۱۱).
  • A text box and an Add button send a POST to your API.یک جعبه‌ی متن و یک دکمه‌ی Add یک درخواست POST به API شما می‌فرستند.
  • The list below shows the result of GET /products.فهرست پایین نتیجه‌ی GET /products را نشان می‌دهد.

3 The frontend's DockerfileDockerfile مربوط به frontend Doneانجام شد

Create frontend/Dockerfile. Same pattern as the API (Lessons 19 and 22):

frontend/Dockerfile را بسازید. همان الگوی API (درس‌های ۱۹ و ۲۲):

frontend/Dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
EXPOSE 8501
CMD ["streamlit", "run", "app.py", "--server.address", "0.0.0.0", "--server.headless", "true"]
--server.address 0.0.0.0
Listen on all addresses of the container, like uvicorn's --host 0.0.0.0 (Lesson 22).روی همه‌ی آدرس‌های کانتینر گوش بده، مثل --host 0.0.0.0 در uvicorn (درس ۲۲).
--server.headless true
Just run the server: don't try to open a browser or ask questions inside the container.فقط سرور را اجرا کن: سعی نکن داخل کانتینر مرورگر باز کنی یا سؤال بپرسی.

Streamlit uses port 8501, hence EXPOSE 8501. Create frontend/.dockerignore so the build files stay out of this image (Lesson 20):

Streamlit از پورت 8501 استفاده می‌کند، برای همین EXPOSE 8501. frontend/.dockerignore را بسازید تا فایل‌های ساخت بیرون از این ایمیج بمانند (درس ۲۰):

frontend/.dockerignore
Dockerfile
.dockerignore

⚠ The API's COPY . . (Lesson 22) copies all of ~/shop-api, and now that includes the frontend folder! Open ~/shop-api/.dockerignore and add a line frontend, so the API image doesn't get the frontend's files.

⚠ COPY . . در API (درس ۲۲) همه‌ی ~/shop-api را کپی می‌کند، و حالا پوشه‌ی frontend هم جزو آن است! ~/shop-api/.dockerignore را باز کنید و یک خط frontend اضافه کنید، تا ایمیج API فایل‌های frontend را نگیرد.

4 Update compose.yamlبه‌روزرسانی compose.yaml Doneانجام شد

Open ~/shop-api/compose.yaml. Add the frontend service at the top, and remove the ports lines from api:

~/shop-api/compose.yaml را باز کنید. سرویس frontend را در بالا اضافه کنید و خط‌های ports را از api حذف کنید:

compose.yaml
services:
  frontend:
    build: ./frontend
    ports:
      - "8501:8501"
    environment:
      API_URL: http://api:8000
    restart: unless-stopped
  api:
    build: .
    environment:
      DATABASE_URL: postgresql://ali:secret@db:5432/shop
    restart: unless-stopped
  db:
    image: postgres:alpine
    env_file: db.env
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
build: ./frontendBuild this service's image from the Dockerfile in the frontend folderایمیج این سرویس را از Dockerfile داخل پوشه‌ی frontend بساز
"8501:8501"Your browser reaches the frontend on localhost:8501مرورگر شما روی localhost:8501 به frontend می‌رسد
API_URL: http://api:8000The frontend finds the API by its service name api (Lesson 13), on its own port 8000frontend، API را با نام سرویسش api (درس ۱۳) روی پورت خودش 8000 پیدا می‌کند
api: no portsapi: بدون portsOnly the frontend needs the API, and it's inside the network. Your browser doesn't need to reach the API directly (same idea as db in Lesson 13)فقط frontend به API نیاز دارد و آن داخل شبکه است. مرورگر شما لازم نیست مستقیم به API برسد (همان ایده‌ی db در درس ۱۳)

7 The API is privateAPI خصوصی است Doneانجام شد

Try to reach the API directly from your PC, like in Lesson 22:

سعی کنید مثل درس ۲۲ مستقیماً از کامپیوترتان به API برسید:

bash
curl localhost:8000/products
output
curl: (7) Failed to connect to localhost port 8000 after 0 ms: Couldn't connect to server

❌ From your PC, the API is unreachable, because it has no ports. Yet the web page works, because the frontend talks to api inside the project's network.

❌ از کامپیوتر شما، API در دسترس نیست، چون ports ندارد. با این حال صفحه‌ی وب کار می‌کند، چون frontend داخل شبکه‌ی پروژه با api صحبت می‌کند.

🔑 Open only what users need: here, just the frontend. The API and the database stay inside, where outsiders can't reach them. That's safer, and it's how real apps are deployed.

🔑 فقط چیزی را باز کنید که کاربران لازم دارند: اینجا فقط frontend. API و دیتابیس داخل می‌مانند، جایی که غریبه‌ها به آن‌ها دسترسی ندارند. این امن‌تر است و برنامه‌های واقعی همین‌طور منتشر می‌شوند.
